# SAMPLE_VIDEO.mp4 자료 적합성 확인

## 결론

첫 관문 완료 전환과 UI 소실·복귀를 검증하기에 적합하다. 아직 학습 모델을 실행한 결과가 아니라 OpenCV로 추출한 프레임의 육안 검토다. 영상 전체의 모든 프레임을 검수한 것은 아니다.

원본 경로: `/Users/huisoo/Downloads/SAMPLE_VIDEO.mp4`. 원본을 수정하지 않았다. 검토용 프레임과 메타데이터는 `outputs/video-review/`에 저장했다.

## 실제 읽은 메타데이터

- 3440×1440, 약 59.998fps, 메타데이터 기준 1,741프레임 / 약 29.017초.
- OpenCV FFMPEG 백엔드로 디코딩 성공.
- 프로젝트의 기존 Mac Python 3.9.6 가상환경에 opencv-python-headless 4.11.0.86, NumPy 2.0.2를 설치하여 검토했다. 기존 Windows 개발 기준 Python 3.11의 설치 검증과는 별개다.
- headless는 별도 이미지 창을 띄우는 GUI 기능이 없는 OpenCV 배포다. 영상 읽기와 파일 출력은 가능하다. 향후 일반 opencv-python 설치 환경과 통합할 때 두 배포를 같은 환경에 중복 설치하지 않는다.

## 표본 프레임에서 확인한 내용

| 표본 시각 | 왼쪽 위 관문 표시 |
| --- | --- |
| 0초부터 7.25초까지 확인한 표본 | 1관문 진행중 / 2관문 진행 전 |
| 7.50초 | 1관문 완료 / 2관문 진행중 |
| 7.73, 9.67, 11.60초 부근 | 같은 상태 유지 |
| 13.53, 15.47, 17.40초 부근 | 관문 UI가 보이지 않는 화면 전환 구간 |
| 19.33초 이후 확인한 표본 및 28.50초 | 1관문 완료 / 2관문 진행중 표시 재확인. 일부 구간은 어둡게 표시됨 |

시각은 샘플링 목표 시각이며 프레임 정확도의 이벤트 정답 시각으로 확정하지 않는다. 표시 변화는 확인한 표본 기준 7.25~7.50초 사이에 있다. 다음 단계에서 전환 주변 프레임의 실제 타임스탬프와 라벨을 더 촘촘하게 확인한다. 진행중 아이콘은 사용자가 정의한 UI 상태를 의미하며 실제 전투 개시 여부까지 추론하지 않는다.

마지막 메타데이터 프레임 인덱스(1740)의 임의 접근 디코딩은 실패했다. 28.50초 프레임은 읽었다. 끝 지점 실패만으로 원본 영상 손상이라고 결론 내리지 않는다. 최초 overview 이미지의 마지막 칸은 읽기 실패 자리이므로 실제 검은 프레임으로 해석하지 않는다. 비교 자료는 `before-after.jpg`와 `transition.jpg`를 사용한다. 전체 순차 디코딩 무결성 검사는 아직 하지 않았다.

## 이 영상에서 만들 수 있는 테스트

1. 두 관문 각각의 상태 및 박스 탐지, 진행중/완료/진행 전 세 클래스의 사례 확보.
2. 1관문 완료 전환에 대해 기대 이벤트 1건이라는 테스트 초안 작성.
3. 완료 상태가 반복되어도 추가 이벤트가 없어야 함.
4. UI 소실을 관문 0개 또는 미완료로 바꾸지 않아야 함.
5. 같은 영상 내 UI 복귀가 두 번째 완료 이벤트를 만들지 않아야 함.

마지막 관문 완료, 다른 레이드/캐릭터로 변경, 앱 재시작, 여러 번의 연속 클리어는 이 영상만으로 검증할 수 없다. 화면이 어두워진 상황의 신뢰도와 가림 처리는 추가 검증 대상이다.
