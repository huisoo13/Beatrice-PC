# 스플래시 OBS 준비와 자동 분석

2026-10-07. 메인 창의 시작·정지 버튼을 제거하고 앱 실행부터 자동으로 분석한다.

## 시작 흐름

1. 스플래시 1/3: YOLO와 PaddleOCR를 준비한다.
2. 스플래시 2/3: 앱에 포함한 OBS 내부 프로세스와 libobs·영상·게임 캡처 모듈을 초기화한다. 게임이 없어도 준비한다.
3. 스플래시 3/3: 프로세스를 조회하고 게임이 있으면 캡처 소스를 연결한다. 연결 응답은 최대 3초 기다린 뒤 메인 창으로 이동한다. 실제 게임 프레임은 이후에도 기다릴 수 있다.
4. 게임이 없으면 메인 창에서 기다리고 감지 즉시 분석한다. 게임 재실행이나 대상 변경 시 소스만 교체하며 준비된 엔진을 재사용한다. 새로고침은 기존 작업자를 종료한 뒤 스플래시부터 다시 준비한다.

대상이 바뀌면 연결 명령에 새 번호를 부여한다. 새 대상에 대한 응답을 받기 전에는 공유 메모리 프레임을 전달하지 않는다. 소스 해제 시 공유 메모리의 준비 표시를 지워 이전 게임 프레임이 새 대상의 기록에 사용되지 않게 한다.

## 기록 작업과 종료

기록 전체 삭제와 Drive 복원은 분석 작업자의 보류 응답을 기다린 후 실행한다. 그동안 프로세스 조회로 게임을 찾더라도 분석을 재개하지 않는다. 작업이 완료되거나 복원이 취소·실패하면 현재 게임을 다시 조회하여 자동 재개한다. 복원 준비 중에는 자동 업로드도 시작하지 않는다. 앱 종료나 새로고침에서는 내장 OBS 내부 프로세스까지 정리한다.

외부 OBS 설치는 필요 없다. YOLO 모델·클래스·OCR 판단 규칙은 이번 변경에서 수정하지 않았다.

## 검증

- 전체 회귀 테스트 309개 통과. 자동 감지·재연결, 스플래시 준비 순서, 엔진 재사용, 이전 연결 응답 무시, 삭제·복원의 보류와 자동 재개를 포함한다.
- `python -m tools.probe_obs_startup`: 실제 앱 소유 libobs와 win-capture를 게임 없이 준비하고 유지한 뒤 정상 종료했다. `outputs/embedded-obs-probe/startup-test.json`.
- `python -m tools.probe_obs_engine`: 내부 색상 소스의 프레임 전달, 소스 해제 후 이전 프레임 폐기, 같은 엔진에서 재연결과 320×180 → 640×360 크기 변경을 확인했다. `outputs/embedded-obs-probe/engine-test.json`.
- 이번 검증에서는 실제 게임 입력·완료 기록이나 Google Drive 서버 데이터를 변경하지 않았다. 실제 게임의 전체 시작 흐름과 배포 EXE 재빌드는 별도 확인이 필요하다.

## 종료 후 잔존 확인

`python -m tools.probe_app_shutdown --mode main`과 `--mode splash`로 실제 Qt 종료 경로와 내장 OBS 프로세스를 확인했다. 두 경우 모두 OBS 자식 프로세스는 종료 코드 0으로 종료했고 분석 작업자·프로세스 감시·OBS 상태 읽기 스레드는 남지 않았다. 공유 메모리와 로그 파일도 닫혔다. 결과는 `outputs/embedded-obs-probe/shutdown-main.json`, `shutdown-splash.json`이다.

이 검증은 임시 데이터와 모형 인식기로 실행하고 실제 내장 OBS를 사용했다. 게임 연결과 네트워크 작업은 시작하지 않았다. 일반 종료는 진행 중인 초기화·분석이 종료 요청을 확인한 후 자원을 정리하므로 즉시 프로세스가 사라지지 않을 수 있다. OBS 종료가 3초 이상 지연되면 앱이 만든 해당 프로세스를 강제 종료한다. Drive 작업 중에는 완료될 때까지 종료 요청을 보류한다.

기존 앱을 완전히 종료하고 `Run-Beatrice.cmd`로 다시 실행하면 적용된다.
