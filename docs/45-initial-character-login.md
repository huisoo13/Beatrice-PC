# 최초 캐릭터 접속

최초 접속도 기존 캐릭터 YOLO 모델의 확장으로 처리한다. 별도 YOLO 모델을
추가하지 않는다. 활성 모델/클래스의 최신 목록은 README 상단 표와 config를 확인한다.

## 화면과 상태

1. `server_table`: 서버 표를 관측하면 이전 캐릭터와 완료 문맥을 해제한다.
   서버 목록 문자열은 OCR하지 않는다.
2. `selected_character_card`와 카드 내부 `selected_character_name`: 선택 화면을 판단한다.
   `game_start_button`은 보조 신호이며 버튼 미탐지가 이름 OCR을 막지 않는다.
   파란 선택 표시가 있는 카드에 포함된 `selected_character_name`만 OCR한다.
   이름은 기존과 같이 2~12자 검증, 두 전처리 OCR 일치, 연속 3회 확인을 거친다.
   작은 이름은 실제 탐지 카드 전체를 **동일 YOLO 모델**로 재검사해 위치를 얻는다.
   카드 안의 고정 비율이나 고정 좌표로 이름을 자르지 않는다.
3. 비밀번호 창에서는 입력 내용을 읽지 않고 앞서 읽은 대상을 보관한다.
   선택 이름 변경 시 후보를 다시 검증하며 서버 선택 복귀 시 폐기한다.
4. `loading_progress`: 실제 로딩 진행 막대의 발광 표식을 관측한 경우에만 접속 중으로 전환한다.
   기존 `loading_indicator`는 오른쪽 아래 **로딩 전 회전 안내**이며 서로 다른 클래스다.
5. 정상 캡처에서 선택 UI·로딩 진행 막대가 모두 사라진 것을 3회 연속 확인하면
   보관한 이름을 확정한다. 검은 화면·모호한 탐지·캡처 누락은 종료 횟수를 초기화한다.
   표식이 흐려져 누락돼도 마지막 로딩 화면과 전체 화면이 거의 같으면 종료로 세지 않는다.

최초 접속 흐름을 놓쳐도 게임 메뉴의 현재 이름을 읽는 기존 경로는 유지한다.
일반 맵 이동은 선택 대상이 없으므로 캐릭터를 바꾸지 않는다. 선택/로딩 관측 없이
180초가 지나면 보관한 대상을 폐기한다. DB에는 기존 정책대로 완료만 저장한다.

## 학습 및 검증 범위

제공된 서버/선택 이미지와 보존된 실제 로딩 프레임, 기존 캐릭터 라벨을 사용한다.
배경 흐림·전체 화면 이동/크기 변형을 포함한다. 주석 좌표는 오프라인 학습 데이터이며
런타임은 실제 예측 박스만 사용한다. 화면 문자열·배경이 달라지는 모든 경우의 정확도를
보장하는 자료는 아니므로 다양한 캐릭터와 배경/해상도의 실제 게임 검증이 필요하다.
현재 새 샘플은 한 접속 흐름에서 얻었으며 재현 평가는 독립 정확도 평가가 아니다.

첫 후보에서 작은 이름과 얇은 막대가 누락되어, 선택 카드 전체를 재탐지하는
확대 학습 자료를 추가하고 로딩 진행 막대 주변 UI까지 라벨 범위를 보완했다.
기존 메뉴의 현재 이름을 놓친 경우에도 실제 탐지 메뉴 전체를 같은 모델로
재검사한다. 추가 YOLO 모델이나 고정 OCR 영역은 사용하지 않는다.

진단 로그에 선택 이름과 서버/선택/전환 전 안내/실제 로딩 신호를 함께 기록한다.
README 모델 목록 검사는 활성 config와 클래스 순서가 달라지면 실패한다.

## 2026-10-01 활성화 및 검증 결과

아래는 첫 활성화 기록이다. **현재 활성 모델과 후속 검증은
[배경 의존 보완 문서](46-login-background-invariance.md)를 우선한다.**

기존 character-regions 모델을 10클래스로 교체했다. 전체 구성은 YOLO 4개,
21클래스이며 공용 PaddleOCR을 유지한다. 학습 실행은
`character-initial-login-0930-v2`, 학습 자료는 133장이다.
활성 가중치 SHA-256은 `96817f2364b29afe0e73849b5d699a9d0276df85d52e3975ec72d8df0f9f9e5c`이다.
교체 전 모델과 설정은 `outputs/retired-models-1001/character-before-initial-login`에 보존했다.

고정된 127장 재현 검사에서 예상 클래스 구성이 일치한 이미지는 116장이다.
불필요한 추가 클래스 탐지는 없었고, 기존 95장 중 종전 모델이 통과한 이미지의
새로운 실패는 없었다. 누락 11장은 기존 이름 영역 5장, 흐림 변형의 게임시작 버튼
2장, 로딩 주변 UI를 흐리게 만든 변형 4장이다. 이 수치는 학습 자료를 포함하는
클래스 구성 검사이며 독립적인 정확도나 모든 해상도 지원을 의미하지 않는다.

실제 접속 기록 46프레임을 재생해 서버 선택, 후이수 선택, 비밀번호 화면에서
대상 유지, 실제 로딩 감지를 확인했다. 기록에는 입장 후 정상 화면이 2프레임만
남아 있어 실제 재생 종료 시에는 접속 중 상태를 유지했다. 마지막 정상 관측을
한 번 더 제공한 별도의 모의 검사에서는 세 번째 확인으로 후이수가 확정됐다.
실제 게임에서 입장 후 세 번째 관측까지의 최종 확인은 추가 테스트가 필요하다.

작은 선택 이름을 놓친 경우 탐지 카드 높이의 5%만큼 여백을 추가해 동일 모델로
한 번 재검사한다. 여백은 탐지 경계 보정이며 이름 OCR 위치는 여전히 YOLO가 정한다.
 서버 표의 문자열 변경 및 새로운 배경에 대한 일반화도 추가 실사용 검증 대상이다.

## 2026-10-14 선택 화면 오탐 방어

카드와 시작 버튼만 잡힌 팝업은 선택 화면으로 처리하지 않습니다. 카드 내부 이름 영역이 필요하며, 확정 캐릭터 해제에는 유효한 동일 선택 이름 3회 연속 관측이 필요합니다. 서버 선택 화면도 확정 해제 전 3회 연속 확인합니다. 처음부터 미확정인 접속은 기존 선택 이름 확정·실제 로딩·종료 3회 확인 흐름을 유지합니다. 비밀번호로 이름이 가려져도 이미 확정한 선택 대상은 보존합니다.

빠른 실제 선택은 유효한 같은 이름 2회에 이어 실제 loginLoading이 관측될 때에도 전환을 인정합니다. 단일 선택 프레임이나 이름 없는 카드·버튼은 이 경로를 사용할 수 없습니다. 이는 빠른 선택에서 세 번째 선택 화면을 놓치는 경우를 위한 독립된 추가 증거입니다.
