# 내장 OBS와 분석 성능 개선 정리

2026-10-06. 사용자가 실제 실행에서 성능이 많이 개선되었다고 확인했다. 아래 수치는 별도의 보존 화면 재생 측정이며, 실사용 피드백을 정량 측정으로 해석하지 않는다.

## 최종 구성

앱에 포함한 libobs 게임 캡처만 사용한다. OBS Studio 설치나 외부 프로그램 연결은 필요 없다. 이전 모니터·창 캡처 구현과 선택 메뉴·설정·의존성·전용 도구를 제거하고, 이미지 수집 CLI도 내장 OBS로 통일했다. 게임 창 식별에 필요한 Windows API는 유지한다.

분석은 기존 YOLO 모델과 한국어 PaddleOCR을 사용한다. 성능 개선 단계에서는 가중치·클래스·탐지 해상도·신뢰도 기준·확정 조건을 변경하지 않았다. 앞서 수행한 던전 모델 보강은 별도 작업으로 아래에 구분한다.

## 승인 순서에 따라 완료한 세 단계

| 단계 | 변경 | 검증 결과 |
| --- | --- | --- |
| OCR 일괄 제출 | 이름·난이도 전처리 이미지들을 한 번에 전달하고 내부 한 장 단위 추론 유지 | 15개 화면의 전체 OCR 결과 동일. 혼합 중앙값 545→528ms로 소폭 감소 |
| CPU 추론 최적화 | YOLO 4스레드, OCR 4스레드와 oneDNN 가속. 가속 실패 시 기존 CPU 방식 재시도 | 20개 화면의 탐지 위치·텍스트·판정 동일. 던전 화면 중앙값 875→431ms, 캐릭터 화면 248→98ms |
| OBS 프레임 대기 | 짧은 읽기 대기는 10ms 재시도하고 인식 상태 유지. 실제 공급 중단과 구분 | 잠깐의 대기가 연속 확정을 끊지 않음. 내부 3440×1440 시험 소스의 중단·복귀 실측 통과 |

여러 이미지를 동시에 추론하는 OCR 방식은 초기 CPU 비교에서 더 느려 제외했다. CPU 최적화 전후의 20장 혼합 분석 중앙값은 301→237ms였으며, 기타 화면에서는 소폭 느려졌다. 모든 장면이 같은 비율로 빨라진 결과는 아니다. 재생 시간에는 캡처·DB 기록·진단 이미지 저장을 포함하지 않는다.

짧은 프레임 대기에서는 중단 메시지를 표시하거나 확정 후보를 초기화하지 않는다. 정상 OBS 게시물 수신이 2초 이상 끊기고 읽기 실패도 250ms 이상 이어지면 공급 중단으로 처리한다. 검은 화면, 오래된 프레임, 최소화 중 동일 픽셀과 화면 동결 보류는 유지한다. 실제 중단에서도 확정된 캐릭터와 완료 중복 방지 상태는 보존한다.

## 함께 저장하는 던전 인식 개선

- 벨가르딘 전투 중 던전 패널 탐지 실패를 추가 학습과 라벨 검수로 보완했다. 같은 제목·난이도의 새 OCR 관측으로 완료 문맥을 복구하며, 같은 플레이의 재생에서 2관문 완료 저장을 확인했다.
- 구원의 종탑 제목 요소를 추가 학습하고 어두운 단계 글자 처리를 보완했다. 던전명·난이도 목록 제한을 제거해 새 탐지 영역에서 읽은 이름과 단계를 검증한다.
- 이 학습·재생 검증은 보존한 실패 화면과 같은 플레이의 자료를 포함하며, 독립 정확도 측정은 아니다.

## 검증·실사용·Git 저장 범위

최종 전체 회귀 테스트 **301개 통과**. 변경분 공백 검사 통과. 사용자가 앱의 캡처 정상 동작과 이후 성능 개선을 실제 실행에서 확인했다. 모든 최소화·가림 상태, 모든 던전의 누락률, 게임 성능 영향을 정량 검증한 결과는 아니다.

코드·설정·학습 명세·문서·검증 도구를 Git에 저장한다. `.gitignore`에 따라 가중치, 원본 이미지, 결과, 가상환경, OBS 엔진 바이너리, 비밀 설정과 실제 기록 DB는 포함하지 않는다. 다른 PC에서는 모델/OCR 리소스와 공식 OBS 엔진을 별도로 준비해야 한다. 최신 구성의 전체 EXE 재빌드는 수행하지 않았다.
