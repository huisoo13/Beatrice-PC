# 던전 패널 YOLO 전환 준비

2026-09-21. 기존 인식 개선 작업은 커밋 `30857a2`로 `origin/main`에 푸시했습니다. 이 문서는 그 이후의 첫 전환 단계입니다.

> 2026-09-22 갱신: 아래는 전용 패널 모델의 준비 기록입니다. 현재 앱은 학습·활성화한 [7클래스 통합 모델](23-integrated-ui-yolo.md)을 우선 사용합니다.

## 당시 상태

전체 게임 화면 → 패널 YOLO → 원본 패널 내부 OCR/관문 탐지 경로를 구현했습니다. **전용 모델 학습 및 실제 해상도별 검증은 아직 하지 않았으며 기본 모드는 기존 방식입니다.** 기존 캐릭터·관문 YOLO 가중치는 던전 패널 클래스를 학습한 모델이 아닙니다.

`config/dungeon-panel.json`의 `mode`를 `legacy`로 두면 기존 동작을 유지합니다. `yolo`에서는 `models/dungeon-panel.pt`가 필요합니다. 모델이 없거나 클래스가 다르면 명시적인 오류를 표시합니다. 탐지에 실패하거나 패널 후보가 여러 개면 던전 정보를 보류하며, 고정 좌표로 몰래 대체하지 않습니다.

## 동작

1. `DungeonPanelDetector`가 전체 게임 창 원본을 YOLO에 전달합니다. 내부 추론 크기는 1280이고 신뢰도 기준은 0.7입니다.
2. 유효한 `dungeon_panel` 탐지가 정확히 하나면 탐지 상자를 기준으로 제목·난이도·관문 영역을 계산합니다.
3. OCR에는 원본 게임 이미지에서 자른 픽셀을 전달합니다. 전체 화면 추론용 축소 이미지로 글자를 읽지 않습니다.
4. 관문 영역은 기존 관문 모델 입력 크기에 맞춥니다. 저장 모듈이 사용하는 박스 좌표는 기존 기준으로 정규화합니다.
5. 기존 관문 HUD·난이도 확인, OCR 합의와 시간 안정화를 적용합니다.

상대 영역은 설정의 `regions`에 0~1 비율로 지정합니다. **현재 값은 초기 배치 가설이며, 라벨링할 패널 경계와 실제 화면에 맞춰 검증·보정해야 합니다.** 패널 테두리를 항상 같은 기준으로 라벨링해야 하며, 화면 해상도만 달라지는 경우와 패널 내부 배치 자체가 달라지는 경우를 구분해야 합니다. 내부 배치가 달라지면 상대 영역 설정을 추가하거나 하위 영역 탐지 모델이 필요합니다.

캐릭터·팝업·로딩의 기존 좌표 의존은 이번 단계에서 변경하지 않았습니다. 던전 패널의 실제 성능을 먼저 검증한 뒤 확대합니다.

## 필요한 데이터

- 브라우저나 데스크톱 전체가 아닌 게임 창 클라이언트 원본 이미지
- 여러 던전명, 짧은 제목과 긴 제목, 여러 난이도 및 싱글 모드
- 1920×1080, 2560×1440, 3440×1440 등 실제 테스트 가능한 해상도·화면 비율
- 서로 다른 UI 배율과 패널 배치
- 던전 패널이 없는 필드·메뉴·로딩 화면도 포함
- train과 val은 서로 다른 플레이 세션으로 구성. 같은 화면의 리사이즈 복사본을 독립 검증으로 사용하지 않음

현재 확인한 사용자 이미지 몇 장과 기존 이름/관문 영역 라벨만으로 다양한 해상도에서의 패널 탐지 성능을 판단할 수 없습니다. 추가 원본과 패널 라벨이 필요합니다.

## 라벨 형식과 학습

예시이며 아래 경로는 실제 파일로 교체합니다. `boxes`는 전체 원본 좌표의 패널 상자이며, 비던전 화면은 빈 배열을 사용합니다. 실제 사용 시 train/val 각각 양성·음성 이미지가 필요합니다.

```json
{
  "classes": ["dungeon_panel"],
  "images": [
    {"path": "frames/dungeon-a.png", "sessionId": "session-a", "split": "train", "boxes": [[0, 36, 360, 240]]},
    {"path": "frames/field-a.png", "sessionId": "session-a", "split": "train", "boxes": []},
    {"path": "frames/dungeon-b.png", "sessionId": "session-b", "split": "val", "boxes": [[0, 27, 270, 180]]},
    {"path": "frames/field-b.png", "sessionId": "session-b", "split": "val", "boxes": []}
  ]
}
```

이미지 경로는 라벨 JSON 파일 위치를 기준으로 해석합니다. 데이터 준비 도구는 원본 해상도를 유지하고 YOLO 상대 좌표 라벨을 생성합니다. 중복 이미지, 같은 세션의 train/val 혼합, 이미지 밖 상자, 양성·음성 누락을 거부합니다. 기존 출력 폴더는 덮어쓰지 않습니다.

```powershell
.venv-win/Scripts/python.exe tools/train_dungeon_panel.py prepare data/annotations/dungeon-panels.json --output outputs/dungeon-panel-dataset
.venv-win/Scripts/python.exe tools/train_dungeon_panel.py train outputs/dungeon-panel-dataset/dataset.yaml --weights models/character-yolo26n-first.pt --epochs 80 --device cpu
```

위 모델은 로컬에 있는 YOLO26n 가중치를 초기값으로 활용하는 예시입니다. 던전 패널 탐지 성능이 이미 있다는 의미가 아닙니다. 다른 로컬 초기 가중치도 지정할 수 있습니다. 학습 결과는 `outputs/training/` 아래에 생성되며, 자동으로 실시간 모델을 교체하거나 설정을 켜지 않습니다.

## 활성화 전 검증

1. 학습에 사용하지 않은 세션·해상도에서 패널 누락과 오탐을 비교합니다.
2. 원본 이미지 위의 패널 상자와 세 상대 영역을 확인합니다. 긴 제목 끝, 난이도 전체, 모든 관문 아이콘이 포함되어야 합니다.
3. 실제 OCR 결과와 기존 모드의 결과를 비교합니다. 텍스트 정답률과 패널 탐지 정확도는 따로 확인합니다.
4. CPU 분석 시간과 짧은 전환 화면 누락 여부를 확인합니다.
5. 검증된 가중치를 설정 경로에 놓고 `mode`를 `yolo`로 변경한 뒤 앱을 재시작합니다.

배포 도구는 `yolo` 모드일 때 설정된 패널 모델도 포함합니다. `%LOCALAPPDATA%/BeatricePC/dungeon-diagnostic.json`에 모드, 패널 탐지 결과와 OCR 관측을 남깁니다.

현재 자동 검증은 전체 68개 테스트 통과입니다. 추가한 패널 테스트는 모의 모델을 이용해 여러 크기·위치의 좌표 변환, 원본 픽셀 전달, 누락/다중 후보 보류를 검사합니다. **실제 YOLO 모델의 해상도 일반화 검증 결과가 아닙니다.**
