# 기간제 아이템 안내가 있는 캐릭터 변경 창

2026-09-28. 캐릭터 변경 대기 전환 누락의 모델 보강 기록.

## 원인

09:18:19~20에 기간제 아이템 목록을 포함한 큰 변경 확인 창이 나타났지만 캐릭터 YOLO의 `switch_dialog`와 `target_name_line`은 missing이었다. 09:18:21~24의 로딩 아이콘·문구는 정상 인식했다. 앞선 확인 창을 관측하지 못해 `변경 확인 창 → 로딩` 조건을 충족하지 못했고, 09:18:45 새 캐릭터 이름이 보일 때까지 기존 캐릭터 확정을 유지했다.

진단 원본은 `outputs/switch-review-0928`에 보존했다. 같은 폴더에 이전 실행의 순환 슬롯도 있으므로 2026-09-28 실행의 sequence 0~145만 이번 재생 대상으로 사용한다.

## 보강 방식

기존 작은 창과 기간제 아이템 안내가 있는 큰 창을 같은 `switch_dialog` 클래스로 학습한다. 대상 이름은 `target_name_line`으로 따로 표시한다. 아이템 목록은 별도의 런타임 영역으로 읽거나 위치를 계산하지 않는다.

기존 학습 자료 76장에 실제 큰 창 1장과 목록 순서·개수(1~5, 7개)·전체 화면 배율 변형 18장을 추가했다. 원본은 6개 항목이다. 총 95장으로 기존 캐릭터 모델을 보강한다. 합성 배경은 인접한 실제 메뉴 프레임의 픽셀로 복원했다. 오프라인 합성·정답 라벨 좌표는 학습 자료 제작에만 사용하며 앱에서는 모델의 실제 탐지 박스만 사용한다.

`tools/prepare_variable_switch.py`가 자료를 준비하고 `tools/evaluate_variable_switch.py`가 창·대상 이름·확인 후 로딩·취소 복귀를 검사한다. 기존 작은 창, 로딩, 12글자 이름 및 다중 해상도 검사도 함께 수행한다. 기간제 목록은 내용과 높이가 변해도 같은 클래스로 학습하는 방식이며 YOLO의 특정 영역을 마스킹하는 전용 기능을 적용한 것은 아니다.

대기 전환 조건과 일반 맵 로딩 제외 정책은 그대로 유지한다. 변경 창만 보였을 때는 기존 캐릭터를 유지하며 후속 로딩이 확인되어야 대기로 전환한다. 검증은 메모리 DB를 사용하며 실제 기록을 수정하지 않는다.

## 학습용 좌표와 실행 중 탐지 좌표

`data/annotations/character-variable-switch-0928.json`의 `boxes[].xyxy`는 각 학습 이미지에 대한 정답 라벨이다. `[왼쪽, 위, 오른쪽, 아래]` 순서의 원본 이미지 픽셀 좌표로, 예를 들어 `[1358, 348, 2083, 1194]`는 그 이미지에서 변경 확인 창의 경계를 표시한다. 이미지마다 위치와 크기가 다르며, 합성 이미지의 라벨도 변형에 맞춰 갱신한다.

학습 도구는 이 라벨을 이용해 모델이 예측한 영역과 정답을 비교한다. 앱은 이 JSON의 좌표를 불러와 화면을 자르지 않는다. 실행 중에는 현재 화면을 YOLO에 입력하고, 실제 탐지된 박스로 OCR 영역을 정한다. 설정의 `trainingManifest`는 학습 자료의 출처를 기록하는 메타데이터이다. 준비 도구의 원본 이미지 crop 좌표 역시 오프라인 자료 제작용이다.

따라서 제거한 것은 실행 중 화면 위치를 미리 가정하는 고정 좌표 방식이다. 학습 정답 라벨이나 모델이 매번 예측하는 좌표를 없앤 것은 아니다. 이 구조가 모든 미학습 해상도에서의 정확도를 보장하지는 않는다.
