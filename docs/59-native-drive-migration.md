# Qt 화면 제거와 WinUI 기능 이전

2026-10-08. UI는 WinUI 3, 분석·로그인·저장은 Python 엔진으로 일원화했다.

## 구성

- `engine_worker.py`: 기존 `desktop.py`의 모델·OBS·게임 감시·완료 기록 작업자만 분리했다. Qt Core의 QThread/Signal은 유지하고 QtWidgets는 사용하지 않는다.
- `account_service.py`: 시스템 브라우저 OAuth, 기존 Windows DPAPI `google-session.bin` 읽기·저장, 로그인 복원·취소·로그아웃을 처리한다. 인증 결과 저장은 엔진 메인 스레드에서만 한다. 취소한 작업의 늦은 결과는 저장하지 않는다.
- `drive_service.py`: 기존 JSON 계약과 DriveClient를 사용한다. 업로드 스냅샷·전송 확인·자동 저장 지연·재시도를 엔진에서 처리한다. 빈 기록과 미확정·테스트 기록 제외를 유지한다.
- `native_bridge.py`: JSON 명령과 상태를 전달한다. `google_login`, `google_cancel`, `google_connect`, `google_logout`, `drive_upload`, `drive_download`, `drive_restore`를 처리한다. 토큰·OAuth 비밀은 상태 메시지에 포함하지 않는다.
- `MainWindow.Drive.cs`: WinUI 설정의 실제 로그인·권한 연결·수동 저장·불러오기·로그아웃과 작업 상태 표시, 복원 확인 창을 제공한다. 샘플 연결 버튼은 제거했다. `--demo`에서는 계정 작업 버튼을 비활성화한다.

기존 Qt의 `Window`, `Startup`, `GoogleLogin`, `DrivePanel`, `PublicContentPanel`, `RecordDetailDialog`와 해당 파일 5개를 제거했다. 공용 데이터 갱신·보기, 보상 상세, 클라이언트 선택, 삭제, 초기화는 기존 WinUI 기능을 유지했다. 테스트·진단·패키지 검증의 구형 모듈 참조도 새 엔진으로 이전했다.

## 기록과 작업 보호

기본 데이터 위치 `%LOCALAPPDATA%/BeatricePC`와 `records.sqlite3`, `google-session.bin`을 그대로 사용한다. 이번 이전에는 DB나 JSON 스키마 변경이 없다. 기존 로그인은 모델 초기화 후 복원하고, 권한이 확인되면 DB에 남아 있는 미전송 완료의 자동 업로드를 재개한다.

불러오기는 작업자의 현재 세대 일시정지 응답을 받은 후 다운로드한다. WinUI에 계정·서버 저장 시각·원격/로컬 기록 수를 보내고, 해당 미리보기 ID의 명시적인 확인 후에만 적용한다. 취소·다운로드 실패·적용 실패 후 분석을 재개하며, 복원 중 새로 실행된 게임도 다시 감지한다. 적용 전 SQLite Backup API로 로컬 DB를 백업한다.

업로드·복원 중 삭제·계정 변경·초기화·수동 클라이언트 변경을 막는다. 자동 업로드 중 기존 분석은 계속할 수 있으며, 추가 완료는 다음 업로드 대상으로 남는다. 종료는 진행 중인 업로드의 검증·DB 전송 확인과 분석/OBS 작업자, 취소한 로그인·다운로드·공용 데이터 네트워크 작업의 종료를 기다린다. 대기 중인 복원 미리보기는 적용하지 않고 폐기한다.

여러 장치 자동 병합·자동 다운로드·주간 초기화는 이 작업에 포함하지 않는다. 매 업로드 새 JSON을 만드는 기존 스냅샷 정책을 유지한다. PySide6는 분석 작업자의 Core 의존성이므로 패키지에서 제거하지 않는다.

## 검증

- Python 회귀 테스트 333개 통과: 로그인 취소·보관 실패·자동 저장·미전송 유지·동시 완료·복원 백업·계정 변경·분석 일시정지·종료 경합을 검증한다.
- 별도 프로세스의 실제 UTF-8 JSON 파이프에서 샘플 로그인 → 저장 → 복원 취소 → 복원 적용 → EOF 종료를 검증한다. 인증과 HTTP는 fixture로 대체하며 사용자 데이터에 접근하지 않는다.
- 별도 Python 프로세스에서 엔진 import 시 `PySide6.QtWidgets`가 로드되지 않는 것을 확인한다.
- 실제 내장 OBS 엔진으로 메인 단계/초기화 단계 종료 시 프로세스·감시 스레드·캡처 자원이 남지 않는 것을 확인한다.
- WinUI Release publish 성공, 1280/640/375px 설정·Drive 화면 및 복원 확인 창을 샘플 모드로 렌더링 검증을 통과했다. 작은 창에서 Drive 상태까지 스크롤할 수 있는지도 확인한다. NuGet 취약성 정보 조회는 네트워크 접근 실패로 NU1900 경고가 남았다.

실제 Google 계정 로그인과 운영 Drive 왕복은 이번 작업에서 실행하지 않았다. Google HTTP/OAuth/JSON 계약 테스트는 유지한다. 실제 계정 왕복 진단은 `tools/check_drive_connection.py`, 자동 저장 진단은 `tools/check_auto_drive.py`로 수행할 수 있다. 후자는 임시 DB와 `integration-test` Drive 영역만 사용한다.


## 재검토 후 보완

2026-10-08 재검토에서 취소/종료 명령과 이미 도착한 로그인 결과가 함께 대기할 때 결과 저장이 먼저 실행되는 경합을 테스트로 재현했다. 명령 큐를 먼저 처리하도록 바꿔 취소·종료가 요청된 로그인 결과를 보관하지 않는다.

WinUI 설정에 누락된 `앱 다시 초기화` 버튼을 추가했다. 엔진이 초기화를 수락한 상태 메시지를 받은 뒤 스플래시를 열고, 기존 작업자의 정리 완료 후 새 작업자를 만든다. 초기화 시작 시 이전 오류·진행 상태를 비우고, 반복 스플래시 종료 상태도 초기화한다. 로그인 복원에 실패한 상태라면 초기화 후 기존 암호화 로그인 정보를 다시 읽어 복원을 시도한다.

분석 오류 시 엔진이 Drive 수동 작업을 거부하는데도 화면에서는 버튼이 활성화되는 불일치도 재현했다. 상태 메시지의 사용 가능 여부를 실제 명령 조건과 일치시켜 버튼을 비활성화한다. 자동 저장의 미전송 기록은 보존한다.

추가 회귀 테스트를 포함해 전체 Python 테스트 333개와 Release publish를 통과했다. WinUI 샘플 검증에는 스플래시 생성·종료를 두 번 반복하는 검사를 추가했다. 실제 Google 계정 왕복 검증은 여전히 별도로 필요하다.
