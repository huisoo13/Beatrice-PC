# 전투·완료 화면의 관문 기록 보완

이 문서는 당시 구현 기록입니다. 최초 완료 저장, 전체 관문 현재 상태, 완료 고정 및 위치 재검증 기한의 최신 정책은 [28번 문서](28-whole-gate-state.md)를 확인하세요.

2026-09-23. 던전명이 표시되지만 관문 완료가 저장되지 않는 실제 기록을 기준으로 보완하고 새 모델을 활성화했습니다.

## 원인

`outputs/gate-completion-review-0923`에 보존한 180프레임 중 던전 영역 미탐지 166개, 관문 영역 누락/포함 관계 실패 13개, 영역 확보 1개였습니다. 영역을 확보한 한 장도 잘못 잡힌 상단 때문에 OCR이 실패했습니다. 전 구간이 `ocr_held`였으며, 화면의 이름은 과거 확정값을 보존한 것이었습니다.

10:58:32(216 프레임)부터 1관문 완료 아이콘이 나타났지만 이후 22프레임 모두 던전 패널을 놓쳤습니다. 이 때문에 관문 상태 YOLO가 실행되지 않았고 저장 단계로 완료 변화가 전달되지 않았습니다. 올바른 영역과 기록 당시 확정된 캐릭터를 제공한 원인 분리 검사에서는 218 프레임에 완료 1건을 임시 SQLite에 저장했습니다. 실제 사용자 DB에는 쓰지 않았습니다.

## 변경

- 던전 영역 모델에 전투 중 4장(58·98·138·178)과 완료 후 2장(218·225)을 먼저 추가했습니다. 첫 재생에서 완료 후 관문 영역 신뢰도가 낮은 프레임이 남아 216·219·230·235를 추가했습니다. 기존 입장 화면과 음성 예제는 유지합니다. 최종 `data/annotations/dungeon-completion-v2-0923.json`은 총 34장(양성 14, 음성 20)입니다.
- 내부 제목·모드 영역과 관문 영역의 라벨 정의는 이전 모델과 같습니다. 캐릭터 모델과 관문 상태 분류 모델은 유지합니다.
- `DungeonObserver`는 YOLO와 현재 OCR/관문 상태로 검증한 영역만 최대 3초 재사용합니다. 재사용할 때도 매번 실제 화면의 제목·모드와 관문 상태를 새로 읽습니다. 재사용으로 3초 기한을 연장하지 않습니다.
- 두 영역이 모두 누락됐거나, 던전 패널이 이전 위치와 IoU 0.9 이상 일치하고 이전 관문 영역을 포함하면서 관문 영역만 누락됐을 때 재사용합니다. 모호하거나 충돌하는 새 후보, 메뉴·변경 팝업·변경 로딩, 해상도 변경, 캡처 중단, 제목/모드 변경, OCR 실패 시 이전 영역을 해제합니다. 검은 화면에서도 현재 관문/텍스트 검증을 통과하지 못하면 즉시 해제합니다.
- 기존 10초 표시 유지와 기록 허용 조건을 구분합니다. `ocr_held`는 계속 저장 근거로 사용하지 않습니다. 재사용 중에도 같은 제목·모드를 실제로 검증한 경우에만 현재 관측으로 전달합니다.
- 앱 상태 문구에 이전 던전명 유지, 영역 재탐지, OCR 재확인, 현재 관문 감지, 상태 변경 확인, 완료 저장/임시 저장을 구분합니다.
- 같은 던전/모드에서 이미 확정한 관문 수는 일시적인 아이콘 누락으로 교체하지 않습니다. 수가 다르면 해당 관측을 보류하고 전체 관문을 재확인합니다. 이전 코드에서 관문 수가 바뀔 때 추적을 재시작해 완료 직전 상태를 잃을 수 있던 경로를 차단합니다.
- 관문 상태 모델에 넘길 때 영역을 320:112 비율로 확장한 뒤 축소합니다. 임의 비율의 YOLO 상자를 강제로 늘려 아이콘 형태가 왜곡되던 문제를 줄입니다. 기준 좌표로 돌아가는 방식은 아닙니다.
- 모드 영역의 하단 여유를 늘리고 실제 글자 높이의 줄을 선택해, 작은 탐지 위치 오차로 제목 끝 획이나 구분선이 모드 OCR에 섞이는 문제를 보완합니다.

## 재생 검사

`tools/replay_recognition_diagnostics.py`는 실시간과 같은 영역 재사용 처리와 `LiveCoordinator`를 실행하고, 메모리 SQLite에 실제 이벤트를 저장합니다. 실행 결과 옆의 `.summary.json`에 이벤트와 미확정 이벤트를 남깁니다. 사용자 DB는 변경하지 않습니다.

진단 링 버퍼에 이름을 확인한 초기 메뉴가 남아 있지 않으면 `--restore-recorded-identity`로 첫 프레임에 기록된 확정 캐릭터를 초기 상태로 복원할 수 있습니다. 이 옵션은 이름 OCR 재검증을 의미하지 않습니다. 나머지 화면 인식과 완료 이벤트 생성은 새로 실행합니다.

```powershell
.venv-win/Scripts/python.exe tools/replay_recognition_diagnostics.py outputs/gate-completion-review-0923 --config config/ui-regions.json --restore-recorded-identity --output outputs/completion-replay.json
```

학습 프레임과 인접 프레임이 같은 세션에 속하므로 재생 결과는 독립 정확도 평가가 아닙니다. 기존 별도 던전 세션·일반 화면·캐릭터 전환 검사도 함께 수행합니다. 해상도는 3440×1440이며 다른 해상도 검증은 이후 과제입니다.

학습은 `dungeon-completion-0923` 50 epoch(freeze 10, lr 0.001) 이후 `dungeon-completion-v2-0923` 25 epoch(freeze 0, lr 0.0005)를 수행했습니다. CPU, imgsz 1280, seed 42이며 신뢰도 기준 0.7은 유지했습니다. 상세 설정은 각 `outputs/training/.../args.yaml`에 있습니다.

## 최종 검증과 활성화

- 자동 테스트 102개 통과. 영역 재사용 기한, 다른 이름/모드·메뉴·검은 화면·캡처 중단·배치 변경에서 해제, 관문 누락 시 기존 관문 수 유지, 완료로 시작한 화면의 신규 저장 방지, 누락을 거친 실제 상태 변화의 단일 저장 등을 포함합니다.
- 이번 180프레임을 새 YOLO부터 재생해 `힐레우스 / 고통의 마녀,세르카 / 매칭 모드 / 1관문` 완료 1건을 SQLite에 저장했습니다. 216 프레임(10:58:32 KST)부터 완료를 관측하고 218 프레임(10:58:34 KST)에 확정했습니다. 첫 캐릭터 이름은 당시 확정 상태를 복원한 것으로, 이 재생 자체에서 이름을 새로 OCR한 것은 아닙니다.
- 전체 재생에서 `ocr_verified` 162, `ocr_held` 16, 최초 확인 중 2프레임이었습니다. 영역 재사용 경로는 8프레임에서 실행됐습니다. 화면 효과 등으로 인식이 계속되지 않는 구간은 여전히 있으므로 모든 프레임을 인식한다고 해석하지 않습니다.
- 실제 DB의 읽기 전용 스냅샷을 메모리 SQLite에 복사해 기존 체크포인트를 이어받고, 같은 기록을 두 번 재생한 결과 저장 건수는 1 → 1이었습니다. 사용자 DB는 변경하지 않았습니다.
- 기존 세르카 입장·1막·일반 화면 55개 검사 통과. 기존 영역 32/32 일치, 추가 영역 오탐 0, 기능 11개·캐릭터 전환 6개·별도 일반 화면 4개 검사도 통과했습니다.
- 캐릭터 모델 SHA256이 기존 설정과 일치함을 확인했습니다. 기존 캐릭터 인식과 던전 정보 10초 유지 정책은 유지합니다.
