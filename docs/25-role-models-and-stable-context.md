# 역할별 YOLO와 확정 정보 유지

2026-09-23 던전 모델의 후속 보완은 [매칭 모드 던전 탐지 보완](26-dungeon-matching-model.md)에 있습니다. 아래 학습·검증 수치는 9월 22일 시점 기록입니다.

2026-09-22. 사용자 승인 순서에 따라 성능 기준 기록, 던전 정보 유지 정책, 역할별 데이터·모델 분리, OCR 최적화, 재생 검증을 진행하고 기본 설정을 활성화했습니다. 현재 운영 기준은 이 문서입니다.

## 활성 구성

`config/ui-regions.json`은 `mode=yolo`, `architecture=split`입니다. 앱 재시작 후 상태에 **캐릭터·던전 분리 탐지**가 표시됩니다.

| 구성 | 파일 | 실행 |
| --- | --- | --- |
| 캐릭터 영역 YOLO, 5클래스 | `models/character-regions.pt`, `config/character-regions.json` | 분석 프레임마다 메뉴·현재 이름·변경 팝업·대상 이름·로딩 탐지 |
| 던전 영역 YOLO, 2클래스 | `models/dungeon-regions.pt`, `config/dungeon-regions.json` | 캐릭터 메뉴/팝업이 보이지 않을 때 던전·관문 패널 탐지 |
| 관문 상태 YOLO | `models/gates-yolo26n-first.pt` | 유효한 관문 패널이 확보되면 상태 분류 |
| 공통 PaddleOCR | `korean_PP-OCRv5_mobile_rec` | 같은 인식기 인스턴스로 캐릭터명·던전명·난이도·문구 읽기 |

기존 통합 모델과 메뉴 보완 모델은 기본 실행에서 로드하지 않습니다. 파일은 복원용으로 남겨뒀습니다. 현재도 모델은 CPU에서 실행하며, 이름별 분류 모델을 만드는 구조가 아닙니다. 캐릭터/던전 모델의 추론 크기 1280, 신뢰도 0.7, 중복 제거 IoU 0.4를 유지했습니다.

## 캐릭터 확인 시간

- 탐지된 메뉴에서 레벨 줄에 가까운 글자 군집부터 검사합니다. 레벨 접두사·2~12글자 이름·두 전처리 OCR 결과의 일치가 확인되면 장식과 아이템 레벨의 추가 OCR을 멈춥니다.
- 넓은 메뉴 이름 줄을 먼저 읽고 실패한 경우에만 직접 탐지된 이름 상자로 보완합니다. 같은 이름을 두 경로에서 항상 중복해서 읽던 처리를 제거했습니다.
- 최초 확정에는 여전히 세 번의 실제 OCR 관측이 필요합니다. 캐시를 관측 횟수로 더하지 않습니다.
- 확정 후 같은 메뉴에서는 이름 OCR을 2초 간격으로 실행합니다. 메뉴/팝업/로딩 감시는 매 프레임 유지하며, 메뉴가 사라지거나 팝업·로딩이 관측되거나 캡처가 중단되면 이름 캐시를 비웁니다. 변경 감시를 유지하면서 초상화 애니메이션마다 같은 이름을 반복 OCR하는 비용을 줄였습니다.
- 팝업을 놓친 채 이름만 바뀌는 특수한 순서는 주기적인 OCR에서 최대 약 2초 후 재확인될 수 있습니다. 처리 시간이 길면 관측 간격도 늘어납니다.

## 던전명·난이도 10초 정책

최초 값은 기존처럼 반복 관측 후 확정합니다. 확정 뒤에는 던전명과 난이도를 한 쌍으로 유지합니다.

1. 미인식·일시적인 다른 값에는 화면의 확정값을 유지합니다.
2. 동일한 새 조합이 10초 이상 연속으로 관측되면 둘을 함께 교체합니다.
3. 기존 값으로 돌아오거나 새 후보가 바뀌거나 미인식이 발생하면 교체 타이머를 초기화합니다. 캡처 간격이 `max_gap`(실시간 5초)을 넘겨도 연속 관측으로 세지 않습니다.
4. 확인된 캐릭터 변경 신호(`suspend`)에서는 던전 표시와 교체 후보를 초기화합니다. 팝업을 열기만 한 경우는 초기화하지 않습니다.

보존된 표시가 현재 OCR과 일치하지 않으면 상태는 `ocr_held`입니다. 이때 기존 이름·난이도를 계속 표시하지만 새 관문 이벤트의 근거로 사용하지 않습니다. 현재 화면과 확정 정보가 다시 일치하면 `ocr_verified`로 돌아갑니다. 따라서 다른 던전에 들어갔을 때 이전 던전 이름으로 완료 기록을 저장하지 않습니다. 새 조합을 검증하는 10초 동안에는 해당 조합으로 관문 이벤트를 기록하지 않는 보수적인 정책입니다.

## 학습과 데이터

`tools/prepare_role_models.py`가 기존 `ui-live-name.json`의 클래스와 학습된 분류 헤드를 역할별로 분리합니다. `data/annotations/character-roles.json`과 `dungeon-roles.json`이 생성되며, 캐릭터는 5클래스, 던전은 2클래스입니다. 제거한 클래스의 화면은 해당 역할의 음성 라벨이 됩니다.

원본/캡처 11장과 명시된 합성 6장, 총 17장의 제한된 자료를 사용했습니다. 캐릭터 양성 12장·음성 5장, 던전 양성 1장·음성 16장입니다. 모든 클래스의 독립 양성 세션을 확보하지 못해 학습 val은 재현 검사로 명시했습니다. 다른 해상도 검증은 수행하지 않았습니다.

- 캐릭터 초기값: 메뉴 보완 모델에서 해당 5개 클래스의 헤드를 추출. `character-roles-v1` 40회(lr 0.0001), `character-roles-v2` 40회(lr 0.001). 첫 단계에서 발견한 던전 영역의 로딩 오탐을 추가 학습 후 재검사했습니다.
- 던전 초기값: 기존 통합 모델의 해당 2개 클래스 헤드를 추출. `dungeon-roles-v1` 40회(lr 0.0001).
- 공통 설정: CPU, seed 42, freeze 10, rect=True, 이미지 크기 1280. 초기 클래스 헤드 추출만으로 끝내지 않고 각각 역할 라벨로 학습했습니다.
- 활성 가중치 SHA256와 학습 실행명은 각 역할 설정 JSON에 기록했습니다. 가중치와 `outputs`는 Git 제외 대상이므로 다른 PC에는 모델 파일도 전달해야 합니다.

## 성능 비교

`tools/benchmark_recognition.py`로 같은 22장(메뉴 10장, 변경/로딩 등 5장, 던전 7장)을 같은 순서로 처리했습니다. 모델 로드, 캡처, JPG 읽기/진단 저장 시간은 제외했습니다. 동시에 학습이나 다른 모델 검사를 실행하지 않은 CPU 측정이며 모든 게임 환경의 속도를 보장하는 값이 아닙니다.

| 지표 | 이전 구성 | 최종 구성 |
| --- | ---: | ---: |
| 메뉴 화면 평균 처리 | 1,553 ms | 327 ms |
| 전체 22장 평균 처리 | 1,187 ms | 594 ms |
| 첫 이름 확정까지의 계산값 | 5.84초 | 1.52초 |

첫 확정 시간은 실제 프레임별 처리 시간과 앱의 최소 0.5초 간격을 적용해 세 번의 OCR 관측이 끝나는 시각을 계산한 값입니다. 실제 게임 창을 다시 조작해 측정한 시간은 아닙니다. 원시 측정은 `outputs/role-baseline.json`, `role-final-benchmark.json`, 비교 요약은 `role-performance-summary.json`에 있습니다. 실시간 진단의 `state.timingsMs`에서도 탐지·캐릭터·던전 단계 시간을 확인할 수 있습니다.

## 검증과 복원

- 자동 테스트 89개 통과: 10초 직전 유지/정확한 경계 교체, 미인식·후보 변경·기존 값 복귀·긴 캡처 간격의 타이머 초기화, 명시적 초기화, 보존 정보로 관문 이벤트를 저장하지 않음, 캐시가 최초 확정 횟수를 부풀리지 않음, 팝업 시 캐시 해제, 메뉴가 보이면 던전 모델 생략 등을 포함합니다.
- 기존 32개 영역·11개 기능·6개 전환 시나리오와 학습에 쓰지 않은 일반 화면 4장의 오탐 검사를 통과했습니다.
- 실제 이름/변경 기록을 새 YOLO부터 다시 재생해 실제 12글자 이름과 힐레우스 확정, 세 번의 변경 대기 전환, 후이수·테베체 재확정을 확인했습니다. 일부 이름 장면은 학습에 포함된 장면의 인접 프레임입니다.
- 역할 학습에 추가하지 않은 별도 실게임 던전 기록 7프레임에서 제목·싱글 모드를 읽고 세 번째부터 확정했습니다. 이는 한 던전 세션의 제한된 확인입니다.
- 원래 실패 장면과 예외를 포함한 기록 재생이며, 사용자 PC에서 변경 후 실게임 전체 흐름을 다시 조작한 검증은 아닙니다. 다른 해상도·UI 배율과 더 다양한 던전·이름은 추가 검증 대상입니다. 로딩 문구 보조 영역과 패널 내부 상대 배치 가정은 여전히 남아 있습니다.

작업 전 코드·설정·통합 가중치는 `outputs/before-role-split`에 보존했습니다. 모델 구성만 복원하려면 그 안의 `config/ui-regions.json`을 원래 설정 경로에 복원하고 재시작합니다. 기존 모델 파일은 원래 경로에도 유지되어 있습니다. 이 설정 복원은 OCR 최적화나 10초 유지 코드를 되돌리지는 않습니다.

```powershell
.venv-win/Scripts/python.exe tools/evaluate_ui_bootstrap.py --config config/ui-regions.json --output outputs/active-check
.venv-win/Scripts/python.exe tools/replay_recognition_diagnostics.py outputs/live-name-failure --config config/ui-regions.json --output outputs/active-replay.json
```

활성화 후 `Run-Beatrice.cmd`로 앱을 완전히 재시작해야 새 모델과 코드가 로드됩니다. 단일 EXE를 새로 빌드한 작업은 아니며, 배포 스크립트가 역할별 가중치를 포함하도록 연결했습니다.
