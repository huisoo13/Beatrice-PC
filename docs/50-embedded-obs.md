# 앱 내장 OBS 게임 캡처

2026-10-06. 외부 OBS Studio나 가상 카메라와 연결하지 않고, 앱에 포함하는 `libobs`와 `win-capture` 모듈을 직접 사용한다. 설치된 OBS 경로·프로필·WebSocket 서버를 조회하거나 실행하지 않는다.

## 사용자 실행

1. 새 코드로 앱을 완전히 재실행한다.
2. 앱은 내장 OBS 게임 캡처를 자동 사용한다.
3. 게임 창을 선택하고 `시작`을 누른다. 기존 YOLO/OCR·완료 DB 경로로 프레임이 전달된다.
4. 게임이 관리자 권한으로 실행 중이면 앱도 같은 권한으로 실행해야 한다. 현재 PC는 이에 해당한다. 소스 실행은 프로젝트의 `run-as-admin.cmd`, 배포 실행은 EXE의 `관리자 권한으로 실행`을 사용한다. UAC는 Windows에서 사용자가 승인한다. 기존 앱을 종료한 뒤 실행해야 단일 실행 잠금과 충돌하지 않는다.

모델이나 캐릭터명 클래스는 변경하지 않았다. 캡처 선택 메뉴와 다른 캡처 방식으로의 전환은 제거했다.

## 구조와 프레임 처리

- `beatrice/obs_capture.py`: 앱 소유 경로에서만 엔진을 찾고 숨겨진 내부 작업 프로세스를 생성한다. 앱과 같은 패키지의 Python 런타임으로 `beatrice.obs_engine`을 실행한다. OBS Studio UI·가상 카메라·외부 서버는 필요 없다.
- `beatrice/obs_engine.py`: 앱의 DLL 검색 경로로 libobs를 초기화하고 지정된 게임 창의 게임 캡처 소스를 만든다. 이름이 같은 게임 창이 여러 개면 다른 창을 선택하지 않도록 연결을 보류한다. 실제 게임 프레임 크기로 영상 크기를 갱신하며 별도의 OCR 고정 좌표는 추가하지 않는다.
- 네이티브 콜백의 BGRA 데이터는 공유 메모리의 최신 한 장으로 복사한다. 게시 전후 시퀀스로 쓰기 도중 프레임을 읽지 않도록 검사한다. 각 게시물은 한 번만 읽고 2초 이상 오래된 전달은 거절한다. 출력은 10fps, 인식 주기는 기존 0.5초다.
- OBS 합성 타임스탬프가 진행되어도 게임 텍스처는 정지할 수 있다. 동일 픽셀이 2초 이상 유지되면 보수적으로 분석을 보류한다. 실제 정지된 정상 장면도 대기할 수 있다. 화면 변화가 다시 확인되면 분석을 재개한다. 처음 2초 동안의 동일 화면은 기존 연속 인식에 사용하므로 게임 원본 프레임의 최신성을 완전히 보장하는 검사는 아니다.
- 최소화 중에는 직전 이미지와 동일한 픽셀을 즉시 보류하며, 변경된 프레임만 전달한다. 최소화 여부를 새 프레임이 있어도 무조건 차단하는 조건으로 사용하지 않는다.
- 검은 화면·접근 거부·엔진 종료는 사유를 표시한다. 캡처 중단은 빈 관측으로 전달하지 않고 확정 상태를 보존한다. 내부 프로세스는 정지 명령의 stdin EOF를 받고 종료한다. 종료가 지연되면 앱이 생성한 해당 프로세스만 종료한다.
- 짧은 읽기 대기는 10ms 후 재시도하며 중단 메시지나 연속 확인 초기화를 발생시키지 않는다. 실제 공급 중단과는 구분한다. [프레임 대기 개선과 최신 검증](54-obs-frame-wait.md).
- 이 모드는 공식 OBS 게임 캡처의 후킹을 사용한다. 게임 보안 프로그램 허용이나 최소화 중 게임 렌더링 진행을 보장하지 않는다.

## 엔진 준비와 배포

`.venv-win/Scripts/python.exe packaging/prepare_obs.py`

공식 OBS 32.0.4 Windows x64 ZIP의 SHA-256을 GitHub 릴리스 자산의 공식 digest와 대조한다. 엔진은 `build/obs-runtime/`에만 준비한다. `obs64.exe`는 포함하지 않는다. DLL, 캡처 도우미, 셰이더와 로케일 등 필요한 데이터를 포함한다.

DirectX 게임에 필요하지 않은 Vulkan manifest는 제외한다. 공식 플러그인은 해당 파일이 존재할 때 공용 ProgramData 후크 파일과 전역 Vulkan 레지스트리를 등록하므로, 파일이 있으면 엔진 초기화를 거부한다. 게임 캡처 파일은 앱의 모듈 데이터 경로를 사용한다. OBS 프로필·자동 업데이트 구성 디렉터리는 생성하지 않는다.

`packaging/build_single_exe.py`는 엔진 준비 없이 배포 파일을 만들지 않는다. 내장 엔진과 엔진 소스 ZIP·GPL 라이선스·Beatrice 대응 소스 ZIP을 함께 패키지에 넣는다. OBS와 결합한 배포물은 GPL 조건을 준수해야 하며, 기존 MIT 원본 라이선스 표시도 유지한다. 별도 종속 DLL의 배포 조건까지 포함한 최종 배포 라이선스 점검은 실제 배포 전에 필요하다.

## 검증

- OBS 단일 경로 정리 후 전체 회귀 테스트 283개 통과. 이전 캡처 전용 테스트를 제거하고 OBS 이미지 수집 CLI의 대상 선택·저장·실패·종료 검사를 추가했다.
- 앱 내부 색상 소스로 libobs → BGRA → 공유 메모리 전달과 색상 변경을 실측했다. `outputs/embedded-obs-probe/engine-test.json`.
- 일반 권한 테스트에서 게임 프로세스 접근 거부를 확인했다. 토큰 정보 조회로 게임 관리자 권한 / 테스트 앱 일반 권한임을 구분했다.
- 사용자 UAC 승인 후 관리자 권한으로 실행한 앱 소유 테스트 프로세스에서 실제 LOSTARK DX11 공유 텍스처 캡처에 성공했다. 포커스가 없는 상태에서 3440×1440 새 프레임을 받았다. 실제 게임 입력이나 완료 DB에는 쓰지 않았다.
- 로그·샘플: `outputs/embedded-obs-probe/frames.jsonl`, `first-frame.jpg`, `obs-engine.log`. 설치된 OBS Studio는 사용하지 않았다.
- 최소화·복원·가림을 직접 조작한 통합 실측 및 실제 던전 완료 양성 기록은 이번에 검증하지 않았다. 모의 테스트에서 최소화 중 변경 프레임·동결 프레임·프레임 지연·검은 화면·중복 게시·종료 창 결과 폐기를 확인했다.
- 배포 스크립트 통합까지 변경했으며 전체 EXE 재빌드 및 별도 깨끗한 PC 실측은 아직 하지 않았다.
