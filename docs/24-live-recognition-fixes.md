# 실게임 진단 기반 인식 수정

후속 적용: [역할별 모델, 이름 확인 속도 및 던전 정보 10초 유지](25-role-models-and-stable-context.md). 아래 보완 모델 구성과 OCR 동작은 해당 후속 단계에서 변경됐습니다.

2026-09-22. 기존 통합 YOLO 모델의 학습 재현 검사 통과 후 실게임에서 발생한 세 가지 문제를 저장된 게임 프레임과 JSON으로 조사했습니다. 가중치를 바꾸거나 탐지 신뢰도 기준을 낮추지 않고 아래 후속 처리를 수정했습니다.

## 이름 길이와 초상화 차이

실제 `힐레우스` 메뉴에서는 `game_menu`만 탐지되고 `current_name_line`이 누락됐습니다. 글자 수를 3으로 제한한 코드 때문은 아니었으며, 작은 이름 영역 탐지에만 의존한 것이 문제였습니다. 또한 텍스트 군집을 자를 때 레벨과 이름 사이 공백을 분리하면 긴 이름만 남고 `Lv.` 검증을 통과하지 못했습니다.

탐지된 메뉴의 초상화 부분에서 노란색 글자가 있는 수평 줄을 찾아 넓게 OCR합니다. 레벨 접두사와 2~12글자 이름, 두 전처리 결과의 합의, 유일한 후보 조건을 검증합니다. 넓은 줄의 검증된 결과를 직접 이름 상자의 결과보다 우선하여 긴 이름의 끝이 잘리는 위험을 줄입니다. 레벨과 이름 사이 공백은 줄 높이에 맞춰 연결합니다. 메뉴 탐지가 없거나 팝업/로딩 중이면 이 경로는 사용하지 않습니다.

## 확인 뒤 로딩 전의 메뉴 프레임

실제 기록 60번은 변경 팝업, 61번은 팝업이 닫힌 메뉴, 62번은 로딩 표시였습니다. 기존 코드는 61번을 취소로 처리하여 62번의 로딩도 변경 근거로 사용하지 못했습니다.

일반 메뉴가 2초 이상 지속될 때 취소 복귀로 확정합니다. 그 전에는 최근 팝업 의도를 유지하되 기록을 중단하지 않습니다. 검증된 로딩 표시를 보면 대기로 전환합니다. 로딩 YOLO가 일부 초상화에서 표시를 놓치는 경우에는 메뉴가 탐지된 동안 기존 창 우하단 영역에서 문구와 청록색 아이콘을 함께 검증합니다. 이 보조 경로는 진단에 `source=window_corner_verified`로 기록합니다. 따라서 로딩에는 창 모서리 기준 좌표 의존이 남아 있습니다.

확인/취소 클릭을 직접 관측하는 방식은 아닙니다. 취소 직후 2초 이내에 다른 로딩이 발생하는 특수한 순서는 추가 검증 대상입니다. 팝업 없이 로딩만 나타나거나 검은 화면만 나타나는 경우 캐릭터를 초기화하지 않습니다.

## 던전 OCR 및 연속 확인

새 기록에서 던전/관문 패널은 탐지됐습니다. 패널 위치가 몇 픽셀 움직이면 난이도 OCR 상단이 101픽셀까지 내려가 `싱글`을 `징글`로 읽었습니다. 난이도 상대 영역의 상단을 0.29에서 0.25로 넓혀 글자 상단 여백을 확보했습니다.

같은 던전명도 공백의 차이로 연속 확인 횟수가 초기화됐습니다. 시간 안정화는 기존 OCR 비교용 정규화 키로 같은 글자열을 비교하고 표시 문자열은 안정적으로 유지하도록 바꿨습니다. 실제 글자가 바뀌면 다시 확인합니다. 관문과 지원 난이도 검증은 유지합니다.

## 확인 결과 및 한계

- 자동 테스트 81개 통과. 팝업→짧은 메뉴→로딩, 취소 복귀 지속, 이름 줄 레벨 보존, 던전명 공백 변화 회귀 검사 포함.
- 실제 캐릭터 기록 109프레임 재생: 힐레우스 확정, 세 번의 변경에서 대기 전환, 뒤의 메뉴가 기록된 후이수와 테베체 확정 확인. 마지막 변경 후 메뉴는 기록에 없으므로 마지막 캐릭터 재확정은 이 자료로 검증하지 않았습니다.
- 실제 던전 패널 7프레임 모두 난이도 `싱글 모드`를 검증했고, 세 번째부터 던전명과 난이도가 `ocr_verified`로 유지됐습니다. 던전은 `1막: 대지를 부수는 업화의 궤적`입니다.
- 2~12글자 합성 텍스트 11종 OCR 통과. 이는 모든 실제 이름/글꼴/배경의 검증을 대신하지 않습니다.
- 기존 재현 자료의 32개 영역과 기능/전환 검사 및 별도 일반 화면 4장의 오탐 검사를 통과했습니다.

실제 기록 재생은 당시 저장된 통합 YOLO 탐지 결과를 사용하고, 저장된 JPG에서 OCR·관문 및 시간 상태를 다시 계산했습니다. 실시간 캡처 전체 경로의 재실행과는 구분합니다. 자료 및 보고서는 Git 제외 경로인 `outputs/live-failure`, `outputs/live-dungeon-failure`, `outputs/live-fixed-character.json`, `outputs/live-fixed-dungeon.json`에 있습니다. 재생 도구는 `tools/replay_recognition_diagnostics.py`입니다.

앱을 종료하고 `Run-Beatrice.cmd`로 다시 실행해야 수정이 적용됩니다. 다른 해상도 및 UI 배율 검증은 아직 남아 있습니다.

## 후속: 확인 중 반복 및 실제 12글자 이름

다음 실게임 기록에서 이름 확인이 반복되는 원인은 금색 초상화 장식이 레벨 줄과 같은 세로 구간을 차지해, 행 전체 픽셀 합산으로 둘을 하나의 큰 줄로 묶은 것이었습니다. 금색 픽셀을 가로 연결한 군집의 높이·가로세로 비율을 검사해 문자 높이의 군집만 줄 후보로 사용하도록 수정했습니다. 시간 확정 조건을 완화하지 않았습니다.

실제 12글자 `그냥열두글자확인하기위한` 화면은 `game_menu`부터 누락됐습니다. 해당 실제 메뉴 1장과 금색 장식 메뉴 1장을 기존 15장에 추가해 17장으로 `ui-live-name-v4`를 40회 보완 학습했습니다(CPU, 1280, freeze=10, seed=42). 라벨은 `data/annotations/ui-live-name.json`입니다. 학습 재현용 구성이며 독립 정확도 평가가 아닙니다.

새 모델 단독 사용 시 기존 던전 기능 검사에 회귀가 있어 전체 모델을 교체하지 않았습니다. 기존 `models/ui-regions.pt`는 유지하고 메뉴가 missing인 경우에만 `models/ui-menu-recovery.pt`를 추가 실행합니다. 보완 모델에서 단일 메뉴가 탐지되면 누락된 캐릭터 관련 클래스만 보충합니다. 기존 던전·관문 결과는 교체하지 않습니다. 메뉴 보완 결과에는 `source=menu_recovery_yolo`가 남습니다. 전체 프레임당 YOLO 호출은 기본 1회, 메뉴 누락 시 최대 2회입니다. 배포 도구는 보완 모델도 포함합니다.

보완 모델 SHA256: `f82b9c01f9e81193d7382ffbd1787be0e3d0e72a4a7c66a695c2e76eb21115bb`.

최종 구성으로 저장 JPG에 YOLO부터 다시 실행한 결과 실제 12글자 이름은 기록 5번에서, 힐레우스는 기록 73번에서 `confirmed`가 됐습니다. 결과는 `outputs/live-name-final.json`이며, 학습에 포함한 장면의 인접 프레임도 포함되므로 독립 플레이 세션 검증으로 해석하지 않습니다. 기존 32개 영역·기능/전환 검사와 일반 화면 오탐 검사, 자동 테스트 83개를 통과했습니다. 합성 글자 길이 검사만으로 실제 모든 초상화·배경에서의 안정성을 판단할 수 없다는 점을 후속 검증 기준에 반영합니다.
