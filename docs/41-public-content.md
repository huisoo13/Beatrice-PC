# 공개 Google Drive 공용 데이터 읽기

2026-09-28. Google 로그인과 별개로 공개 폴더의 `JSON/ContentJSON.json`을 읽습니다.
개인 기록 저장용 appDataFolder·OAuth 토큰·SQLite 기록은 이 기능에서 사용하지 않습니다.

## 연결 설정

- 최상위 공개 폴더: `1DACO6WmH4qjsVfCyYoSrW-bRCiUz5pLz`.
- 앱은 최상위 폴더에서 이름이 `JSON`인 폴더를 찾고 그 안에서 `ContentJSON.json`을 찾습니다.
- 폴더 ID·하위 폴더명·파일명·확인 주기는 `config/public-content.json`에 있습니다.
- API 키는 프로젝트/앱 최상단의 `google_drive_api_key.txt`에서 읽습니다.
  다른 위치를 쓰려면 `BEATRICE_DRIVE_API_KEY_FILE`에 파일 경로를 지정합니다.
- 키 파일은 Git에서 제외하며 로그·캐시·오류 메시지에 키를 남기지 않습니다.
- Google Cloud의 API 키 제한은 Google Drive API로 설정합니다. 사용자가 Google 로그인할 필요는 없습니다.
- 공개 폴더와 하위 파일은 링크가 있는 모든 사용자에게 읽기 권한이 있어야 합니다.
- 배포 스크립트는 키 파일을 자동으로 포함하지 않습니다. 실행 환경에 별도로 배치하거나 환경 변수로 지정해야 합니다.

## 앱 동작

데이터 흐름은 **공유 폴더 → JSON 다운로드 → 형식 검증 → 로컬 캐시 저장 → 앱에서 캐시 내용 사용**입니다.
다음 실행에서는 보관된 데이터를 먼저 읽고, 백그라운드에서 최신 여부를 확인합니다.
최초 실행에 인터넷 연결이 없고 캐시도 없으면 공용 데이터만 사용할 수 없는 상태로 표시합니다.

메인 창의 공용 데이터 영역에서 상태를 확인할 수 있습니다.

- 메인 창을 열 때와 이후 1시간마다 백그라운드에서 변경 여부를 확인합니다.
- `공용 데이터 갱신`으로 즉시 확인할 수도 있습니다.
- `공용 데이터 보기`는 던전·난이도·관문·gold·fee·귀속 비율을 표로 보여줍니다.
- 같은 파일 ID와 MD5 체크섬이면 검증된 로컬 내용을 재사용하여 파일 본문 다운로드를 생략합니다.
- 파일이 교체되어 ID가 달라져도 폴더명과 파일명으로 다시 찾습니다.
- 같은 이름의 폴더/파일이 여러 개면 임의 선택하지 않고 오류를 표시합니다.
- 다운로드 시 체크섬과 JSON 구조를 확인한 뒤 임시 파일을 원자적으로 교체하여 보관합니다.
- 캐시 위치는 앱 데이터 폴더의 `public-content/content-cache.json`입니다.
  기본 런처로 실행하면 `%LOCALAPPDATA%\BeatricePC\public-content\content-cache.json`에 저장합니다.
  `BEATRICE_DATA_DIR`을 별도 지정해 실행하면 해당 데이터 폴더를 사용합니다.
- 네트워크 오류·권한 오류·손상된 JSON·저장 실패 시 마지막 정상 캐시를 유지합니다.
- 앱 종료·새로고침 후 늦게 도착한 결과는 디스크에 적용하지 않습니다.

현재는 공용 자료의 조회·검증·캐시·표시까지 연결했습니다.
골드 수익 계산, 개인 기록과의 결합, OCR 난이도/던전 설정 갱신은 아직 적용하지 않습니다.
원본 파일 값은 수정하거나 자동 교정하지 않습니다.

## JSON 형식

```json
{
  "던전명": {
    "하드": {
      "1관문": {
        "gold": 10000,
        "fee": 3200,
        "bound_percentage": 0.5
      }
    }
  }
}
```

UTF-8 JSON 객체이며 최대 4 MiB입니다. 관문은 1~8관문을 연속으로 포함하고,
gold/fee는 0 이상의 정수, bound_percentage는 0~1 숫자입니다.
동일 JSON 키 중복·NaN·무한대·잘못된 구조를 거부합니다.
화면의 귀속 비율은 `bound_percentage × 100`으로 표시합니다.
