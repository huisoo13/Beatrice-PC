# 완료 이력 보존과 주간 중복 방지 검증

2026-10-08. 완료 이력은 계속 누적하고, 주간 반복 판정만 한국 시간 수요일 오전 6시에 초기화한다. PC와 iOS가 서로 다른 파일을 쓰는 저장 계약과 실제 플레이 검증 결과를 정리했다.

## 최종 동작

- WinUI 3가 화면을 맡고 Python 엔진이 분석·기록·Google 인증·Drive 저장을 처리한다. Qt 화면 5개는 제거하고 Qt Core의 작업자 신호·스레드는 유지한다. [이전 구조](59-native-drive-migration.md).
- `records.sqlite3`의 `completion_history`는 전체 완료 이력이다. 화면과 Drive 내보내기는 이 테이블을 읽는다.
- `gate_states`는 관문별 인식 체크포인트다. `weekly_repeat.period_start` 이전의 완료는 이번 주 중복 판정에서 제외한다. 초기화는 이력을 지우거나 체크포인트 테이블을 일괄 삭제하지 않는다.
- 실행 중에는 약 1초 간격으로 주간 경계를 확인하고 분석 작업자가 일시정지에 응답한 뒤 반복 기준과 추적기를 초기화한다. 앱이 꺼져 있으면 다음 실행에 적용한다.
- 주간 초기화만으로 저장된 ID·시각·업로드 배열·미전송 리비전·전송 확인은 바뀌지 않는다. 다음 주 완료가 생기면 새 ID의 이력을 추가한다.
- 이전 구현의 `weekly-records/*.sqlite3`가 있으면 전체 완료 이력을 한 번 복구한다. 소스 파일은 보존하고 로컬 복구 표식으로 재실행 중복을 막는다.

## PC와 iOS 파일 계약

PC는 앱 전용 Drive 공간의 `PC.json` 하나만 생성·갱신한다. 파일 교체 전 로컬 백업을 검증하고 교체 후 서버에서 읽어 확인한다. iOS는 PC 파일을 읽고 자신의 `iOS.json`만 갱신하는 별도 작업이다.

JSON은 `characterName`, `dungeonName`, `difficulty`, `gate`, `state`, `recordID`, `updatedAt`의 7개 필드를 갖는 배열이다. 주차·초기화·삭제 표시는 추가하지 않는다. 새 완료 ID는 `br2_`와 UUID4의 소문자 32자리 hex이며 Drive 메타데이터의 schemaVersion은 3이다. 기존 br1 ID와 schemaVersion 1·2 입력도 읽는다.

같은 주의 같은 캐릭터·던전·관문은 중복 저장하지 않는다. 다음 주 같은 관문을 완료하면 별도 ID로 저장한다. iOS 가져오기는 없는 ID를 추가하고 같은 ID의 더 최신 updatedAt만 적용한다. 과거 주라는 이유나 PC 파일에 없다는 이유로 iOS 이력을 삭제하지 않는다. 사용자 확인 상태도 ID별로 보존한다. [전체 계약과 제한](38-google-drive.md).

이력은 계속 누적되므로 단일 JSON의 크기는 기록 수에 따라 증가한다. 현재 4 MiB/10,000행 제한을 유지한다. 주간 20행 기준 연간 약 1,040행이며 일반적인 이름 길이는 연간 약 250 KiB 수준이다. 기록마다 별도 Drive 파일을 만드는 방식은 사용하지 않는다.

## 테스트 데이터 준비

사용자 요청으로 로컬 실제 DB를 백업한 뒤 다음 데이터를 넣었다. 던전명·난이도·관문·보상 연결은 저장된 공용 JSON의 정확한 키를 사용했다. 날짜와 시각은 모두 2026년 한국 시간이다.

| 캐릭터 | 던전 | 난이도 | 관문 | 저장 시각 | isTest |
|---|---|---|---|---|---|
| 힐레우스 | 고통의 마녀, 세르카 | 하드 | 1 | 10-03 00:00:00 | true |
| 힐레우스 | 고통의 마녀, 세르카 | 하드 | 2 | 10-03 00:00:01 | true |
| 테베체 | 고통의 마녀, 세르카 | 하드 | 1 | 10-04 00:00:02 | true |
| 테베체 | 고통의 마녀, 세르카 | 하드 | 2 | 10-04 00:00:03 | true |
| 힐레우스 | 4막: 파멸의 성채 | 하드 | 1 | 10-08 17:21:40 | true |
| 힐레우스 | 4막: 파멸의 성채 | 하드 | 2 | 10-08 17:21:41 | true |

`isTest=true`는 Drive 내보내기에서 제외하는 기존 필드다. 이번 주 중복 판정에서는 같은 주의 테스트 체크포인트도 사용하므로 4막 데이터로 실제 중복 차단을 검사할 수 있다. 이 데이터·DB·인증 정보·진단 이미지 자체는 저장소에 포함하지 않는다. 주입 전 DB 백업은 로컬 `manual-backups`에 있다.

## 실제 플레이 결과

### 이전 주 완료가 이번 주 저장을 막지 않는지

이번 주 시작은 10-07 06:00 KST(`2026-10-06T21:00:00.000Z`)였다. 사용자가 10-08에 힐레우스로 세르카 하드를 실제 플레이했다.

| 관문 | 실제 저장 시각 KST | 결과 |
|---|---|---|
| 1 | 18:07:26.531 | 새 br2 ID로 일반 완료 저장 |
| 2 | 18:17:35.300 | 새 br2 ID로 일반 완료 저장 |

완료 진단의 changedRecords ID와 DB 이력 ID가 일치했다. 새 실제 기록에 isTest 표시가 없고, 이전 주 테스트 이력 2건은 원래 ID·시각·isTest=true로 보존됐다. 즉 이전 주 기록 때문에 새 완료가 차단되지 않았다.

DB의 Drive 변경 리비전과 해당 계정의 확인 리비전도 7/7로 일치했다. 앱의 업로드 후 읽기 검증·확인 경로가 완료된 로컬 상태를 확인한 것이다. 별도 검사 도구로 운영 서버의 현재 파일을 다시 다운로드한 검증은 수행하지 않았다.

### 같은 주 완료를 다시 저장하지 않는지

4막 하드 1·2관문에 1시간 전의 완료 체크포인트를 주입한 뒤, DB 복사본에 isTest 없는 일반 완료 입력을 전달했다. 새 이력 0건·변경 리비전 불변을 먼저 확인했다. 이후 사용자가 실제 플레이했다.

| 관문 | 완료 아이콘 최초 관측 시각 KST | 추가 저장 |
|---|---|---|
| 1 | 18:32:20.097 | 0건 |
| 2 | 18:41:08.726 | 0건 |

진단에서 힐레우스가 confirmed이고 4막 제목·하드 난이도가 ocr_verified였다. 관측된 상태가 1관문 완료/2관문 진행 중, 이후 두 관문 완료로 변했다. 이미 저장된 이번 주 체크포인트의 stableStates는 두 관문 완료로 유지됐으며 changedRecords·events는 빈 배열이었다. DB에는 주입한 2건만 남고 ID·저장 시각·isTest 값은 변하지 않았다.

`changedRecords: []`는 그 관측으로 새로 저장하거나 변경한 기록이 없다는 뜻이다. 빈 배열 하나만으로 성공을 판단하지 않고, 캐릭터·제목·난이도·완료 아이콘이 실제로 인식됐는지와 DB 불변을 함께 확인했다.

이번 실게임은 관문 아이콘을 통한 기록·중복 방지 경로를 검증했다. 관측 중 완료 배너의 글자 검증 실패도 있었으므로 이 결과를 배너 OCR 전체 통과로 해석하지 않는다. 수요일 오전 6시를 실시간으로 넘기는 실게임 테스트도 이번 플레이 범위에는 포함하지 않는다.

## 자동 검증과 재현 명령

전체 Python 테스트 342개, 실제 내장 OBS 엔진의 메인·스플래시 종료 검증을 통과했다. WinUI Release publish와 샘플 화면 검증도 통과했다. NuGet 취약성 정보 서버 연결 실패에 따른 NU1900 경고는 남아 있다.

```powershell
.\.venv-win\Scripts\python.exe -m unittest discover -s tests
.\.venv-win\Scripts\python.exe -m unittest discover -s tests -p test_weekly.py
.\.venv-win\Scripts\python.exe -m unittest discover -s tests -p test_native_bridge.py -k weekly_reset
.\.venv-win\Scripts\python.exe tools/probe_app_shutdown.py --mode main
.\.venv-win\Scripts\python.exe tools/probe_app_shutdown.py --mode splash
.\ui\Beatrice.App\build.ps1 -Publish
```

주간 자동 테스트는 05:59:59/06:00:00 경계, 이력·전송 대기 불변, 새 주의 같은 관문에 별도 ID 생성, 재실행·복원 유지, 과거 DB 복구, 이력 저장 실패의 트랜잭션 롤백을 검사한다. 테스트는 임시 DB를 사용하고 시스템 시각·실제 사용자 기록·Google Drive를 바꾸지 않는다. 실게임 원본 증거는 로컬 `completion-diagnostics/20261008T085530Z-325397f5`에 남아 있다.
