# 골드 보상 여부 인식과 기록 연결

최종 갱신: 2026-10-11.

## 기록 정정

힐레우스의 1관문 기록 `br2_a3df68bc713848a4986e5f61f40d2a68`에서 제목 첫 숫자가 잘려 저장된 `막: 대지를 부수는 업화의 궤적`을 `1막: 대지를 부수는 업화의 궤적`으로 정정했다. 공용 field_name 정확 매칭을 확인하고 싱글 모드 1관문의 기본 보상 3,500·비용 750·귀속 비율 0.5를 연결했다. 사용자가 제공한 같은 플레이의 미획득 보상표를 근거로 `goldReward: false`를 반영했다. 이 기본 금액은 실제 획득을 뜻하지 않으며 주간 합계에는 0으로 반영된다.

기록 ID·캐릭터·관문·expectedGates·observedAt·createdAt을 유지하고 updatedAt과 Drive 전송 revision만 갱신했다. 원래 OCR 문자열은 감사와 이전 실행의 별칭 중복 차단을 위해 보존했다. 변경 전 WAL 포함 DB 백업은 `outputs/gold-reward-review/before-record-correction.sqlite3`, 정정 전후 자료는 같은 폴더의 `record-correction.json`·`no-gold-record-correction.json`에 있다. 업로드를 직접 수행한 것은 아니며 기존 Drive 큐로 전송을 예약한다.

## 탐지와 연결

`config/gold-reward-panel.json`은 보상표 전체 `reward_panel`을 찾는 부모 전용 YOLO다. `config/gold-reward.json`은 실제 crop 안에서 `reward_gate_title`, `gold_reward_present`, `gold_reward_absent`를 찾는 요소 YOLO다. 요소 모델의 초기 학습 `reward_panel` 클래스도 메타데이터에 남지만 실행 중에는 사용하지 않는다. 전체/내부의 학습 간섭을 피하기 위해 두 모델로 분리했다. 기존 캐릭터·던전·완료 표시 모델과 클래스는 변경하지 않는다.

캐릭터가 확정되고 현재 던전 제목이 확인되며 완료 아이콘이 보이는 프레임에서만 실행한다. 전체 화면에서 보상표를 찾고, 실제 탐지 부모 박스를 잘라 관문 제목과 통화 영역을 다시 탐지한다. 부모 테두리 오차를 위해 탐지 폭의 2.5%를 좌우, 높이의 10%를 상단에 여유로 둔다. 글자와 통화 위치는 항상 별도 YOLO 박스로 찾으며 화면 고정 좌표·패널 내 OCR 비율은 사용하지 않는다.

제목 crop은 밝기를 정규화한 뒤 공용 PaddleOCR로 읽는다. 신뢰도 0.8 이상의 정확한 `N관문 돌파` 또는 `던전 종료` 문구를 허용한다. `던전 종료`는 final 범위로 전달하며 탐지 모듈이 관문 번호를 추정하지 않는다. 통화 영역은 골드 행이 있는/없는 클래스를 명시적으로 탐지해야 한다. 골드 탐지 실패나 보상표 부재를 미획득으로 해석하지 않는다. 두 클래스가 충돌하거나 제목·관문·영역이 모호하면 미확인이다. 입장 전 `골드 보상 설정`과 `던전 종료`의 파티 거래 골드는 판단 근거로 사용하지 않는다.

`GoldRewardSession`은 이번 실행에서 새로 저장한 완료 ID만 120초 동안 등록한다. 현재 캐릭터·던전 별칭·난이도·보상표의 관문 번호·해당 관문 완료 아이콘이 모두 맞고 서로 다른 시각의 관측 두 번이 일치해야 저장한다. 분석을 실행하지 않은 throttle 프레임은 관측 수에 넣지 않는다. 서로 다른 결과, 빈/미검증 화면은 연속 확인을 끊으며 3초 이상 간격도 재확인이 필요하다. 캐릭터·클라이언트·던전 전환과 캡처 중단은 등록과 후보를 비운다.

기존 주간 기록을 조회해 임의 연결하지 않으므로 재입장·반복 플레이의 미획득 보상표가 첫 완료의 획득 여부를 바꾸지 않는다. 확인 시 보상 갱신만 발생하며 새 완료 이벤트나 ID를 만들지 않는다. 관문 완료 판단은 기존 완료 아이콘/배너 재확인 규칙을 유지한다.

## JSON과 합계

완료 JSON의 선택 필드 `goldReward`는 true(획득)·false(미획득)·null/없음(미확인)이다. DB v5·Drive JSON v4에 선택 필드로 추가하며 과거 미상 값을 일괄 추정하지 않는다. 원본 OCR과 공용 금액도 그대로 보존한다. `Store.set_gold_reward(record_id, received)`는 미확인에서 확정으로만 갱신하고 같은 값은 변경 없이 반환하며 반대 값으로 덮어쓰기를 거부한다. 이력·주간 체크포인트·Drive 큐는 같은 트랜잭션이다.

주간 합계는 획득 true 또는 미확인 null/없음이고 유효한 공용 금액이 있으면 기본 골드를 일반/귀속으로 나눈다. false는 공용 매칭 유무와 관계없이 0이다. 금액 미연결은 합계에서 제외하고 건수를 표시한다. 미확인 금액이 포함된다는 안내를 표시하며 기록 자체의 goldReward를 true로 추정 저장하지 않는다. 상세 화면은 골드 여부와 공용 데이터의 기본 골드를 따로 표시한다. 더보기 구매 비용은 감지하지 않으므로 합계에서 차감하지 않는다.

구버전 실행은 새 JSON 선택 필드를 지원하지 않으므로 앱을 완전히 재시작해야 한다. iOS 호환 작업은 추후 범위다.

## 학습과 검증 범위

기존 세르카 골드 획득 보상표와 제공된 1막 미획득 보상표를 검토하여 라벨링했다. 밝기 100%·75%·50%·35%, 크기 100%·75%·125%, 전체 화면·부모 crop 5종을 준비한다. 부모 crop은 실제 탐지 경계 오차에 따른 주변 배경·제목 위치 변형을 포함한다. 최종 요소 자료 152장(144개 양성 변형·8개 전체/crop 음성)을 `data/annotations/gold-reward-context-1011.json`으로 관리한다. 부모 자료는 전체 화면 28장(24개 양성·4개 음성)을 `data/annotations/gold-reward-panel-1011.json`으로 관리한다. 입장 전 골드 설정·미니맵만 보이는 화면·EX 하드 파티 거래 보상표는 음성 자료다. 좌표는 학습용 라벨에만 존재한다. 준비는 `tools/train_gold_reward.py [--parent] --output <새 데이터셋 경로>`, 검증은 `tools/evaluate_gold_reward.py --weights <요소 후보> --parent-weights <부모 후보>`, 학습은 기존 `tools/train_dungeon_panel.py`를 사용한다. 원본은 `data/raw/gold-reward-1011/`에 복사해 임시 첨부 파일이 지워져도 준비 도구가 재사용한다.

밝기 변형은 합성 dim이다. 학습 원본과 같은 세션의 다른 시간 프레임도 재생하지만 별도 던전·해상도·새로운 연출의 독립 정확도로 해석하지 않는다. 지원 보상표가 아니거나 가림·강한 dim 때문에 검증되지 않으면 미확인을 유지한다. 관문 없는 콘텐츠의 다른 결과표는 현재 자동 판별 대상이 아니다.

학습·평가·테스트·빌드 결과는 `outputs/gold-reward-review/`에 보존한다. 원본·데이터셋·모델 바이너리는 로컬 관리하고 설정·검토 라벨·도구·문서를 Git으로 관리한다.

## 최종 보상표 보완 (2026-10-11)
