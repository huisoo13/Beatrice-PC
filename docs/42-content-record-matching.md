# 공용 JSON 매칭과 완료 기록 상세

2026-09-28. Drive에서 내려받아 검증한 `public-content/content-cache.json`을 완료 기록과 연결한다. 개인 완료 기록 업로드·복원용 JSON과 공용 보상 JSON은 별개이다.

## 저장 규칙

1. 던전명은 Unicode·공백·구두점 표기를 정리한 뒤 동일 이름을 우선 찾는다.
2. 동일 이름이 없으면 Python 표준 `difflib.SequenceMatcher`로 비교한다. 정규화 이름 5자 이상, 유사도 0.85 이상인 후보가 정확히 하나여야 한다. 이름에 들어 있는 숫자도 일치해야 하므로 다른 막·단계를 숫자 오타로 치환하지 않는다. 유사도는 정답 확률이 아니다.
3. 그 던전 내부에서 난이도를 찾는다. 공백·괄호와 끝의 `모드` 표기 차이를 허용하지만 난이도 자체를 유사 문자열로 추측하지 않는다.
4. 해당 난이도에 관측한 관문 번호가 있어야 한다. 이름·난이도·관문 전체가 확인되어야 치환한다.
5. 후보가 없거나 여러 개면 세 항목 모두 원래 관측값을 유지한다. 가장 높은 점수라는 이유만으로 복수 후보 중 하나를 고르지 않는다.

DB의 `dungeonName`, `difficulty`에는 JSON의 원래 키를 저장한다. `gate`는 기존 DB·Drive 계약에 맞춰 정수로 유지하고, JSON의 `1관문` 같은 키는 `gateName`에 추가하여 리스트에서 표시한다. 관문 없는 레이드는 공용 JSON에 관문 항목이 하나일 때만 연결한다. 여러 관문이 있는 항목의 첫 관문으로 임의 연결하지 않는다. 기존 레이드 전체 완료 범위와 Drive의 관문 0 규칙은 유지한다.

`ocrOriginal`에 치환 전 값, `catalogMatch`에 매칭 상태·정식 경로·공용 파일 ID/버전/체크섬·당시 보상 값을 저장한다. 캐릭터 확인 전 보류 완료를 승격할 때도 이 정보를 유지한다. 관문 아이콘·완료 배너·후속 관문 보완 모두 같은 완료 저장 경로를 사용한다.

완료만 DB에 기록하고, 이미 완료된 동일 캐릭터·던전·관문은 다시 저장하거나 수정하지 않는다. 난이도 변경으로 중복 기록을 만들지 않는 기존 정책도 같다. OCR 표기와 정식 이름의 관계를 확인하여 치환 전후 중복을 방지한다. 기존 기록을 일괄 치환하거나 미매칭 기록을 나중에 자동 수정하지 않는다.

## 기록 클릭

리스트의 행을 한 번 클릭하면 골드(`gold`), 비용(`fee`), 귀속 비율(`bound_percentage`)을 표시한다. 매칭 실패·복수 후보는 연결되지 않았다는 안내를 표시하며 다른 항목 정보를 대신 보여주지 않는다.

저장된 정식 경로가 현재 공용 JSON에도 있으면 최신 값을 표시한다. 현재 데이터가 없거나 경로가 삭제됐으면 저장 당시의 값을 표시하고 출처를 구분한다. 상세 창을 다시 열면 갱신된 데이터가 반영된다. OCR 원문도 함께 표시한다.

이전 버전 또는 개인 Drive에서 복원한 기록도 공백·구두점·난이도 끝의 `모드` 표기 차이를 정리해 상세 정보를 조회한다. 정규화 후 후보가 하나일 때만 연결하며 오타 유사 검색은 하지 않는다. 저장된 기록 자체는 수정하지 않는다. 개인 Drive의 기존 7필드 계약은 유지하므로 OCR 원문·매칭 메타데이터·당시 보상 스냅샷은 개인 Drive 내보내기에 포함하지 않는다. 이 정보는 로컬 DB에 보존된다.

## 실행 및 검증

캡처 작업자의 Store에 로컬 공용 캐시 조회기를 연결했다. 캐시 파일이 바뀔 때만 다시 읽으며 화면 분석 중 네트워크 요청은 하지 않는다. 공용 데이터 갱신은 기존 백그라운드 다운로드 기능이 담당한다. 캐시가 없으면 원문 저장을 계속하고, 갱신 실패 시 마지막 정상 데이터를 유지한다.

- 전체 자동 테스트 227건 통과 후 배너 최초 완료·미매칭 DB 보존 등 2건을 추가해 매칭 테스트 12건을 재검증했다.
- 이름 동일·오타·복수 후보, 난이도/관문 불일치, 숫자 구분, 완료 잠금·중복 방지, 보류 승격, 배너 완료, Drive 직렬화, 캐시 손상, 상세 화면을 검사했다.
- 실제 내려받은 공용 JSON의 모든 경로와 오타 예시를 읽기 전용으로 검사하고 Qt 상세 화면을 렌더링했다. 실제 게임에서 새 완료 기록을 생성하는 검증은 사용자 테스트가 필요하다.
- 테스트 DB는 메모리 또는 임시 파일이며 사용자의 실제 완료 기록은 변경하지 않았다.

앱을 완전히 종료하고 다시 실행해야 새 저장·클릭 동작을 사용한다. 모델 재학습이나 고정 좌표 변경은 없다.
