# WinUI 3 데스크톱 UI 적용

2026-10-07 WinUI 초기 적용 후, 2026-10-08 승인한 주간 클리어 로그 디자인으로 갱신했습니다. 현재 디자인과 검증 기준은 [주간 관문 기록 UI](61-weekly-record-ui.md)를 참고합니다.

## 실행

```powershell
./ui/Beatrice.App/build.ps1
./Run-Beatrice.cmd
```

UI는 `ui/Beatrice.App`의 C# / WinUI 3 / XAML입니다. 실행기는 개발 빌드의 `BeatricePC.exe` 또는 배포 폴더 `native-ui/BeatricePC.exe`를 실행합니다. .NET 8 SDK가 필요하며, 프로젝트의 `outputs/dotnet`이 있으면 우선 사용합니다.

기존 Python YOLO·OCR·내장 OBS·SQLite 분석 작업자는 별도 프로세스로 유지합니다. `app_launcher.py --engine`은 QCoreApplication을 사용하고 QWidget 화면을 만들지 않습니다. 현재 작업자의 QThread 의존성 때문에 PySide6 런타임은 분석 프로세스에 남아 있습니다. 통신은 로컬 표준 입출력의 UTF-8 JSON 줄이며 웹 서버나 네트워크 포트를 열지 않습니다. Python/C 라이브러리 출력은 `runtime.log`로 분리합니다. 입력 명령은 스레드 안전 큐를 통해 메인 스레드에서 처리합니다.

## 적용한 화면과 기능

- 승인한 토큰·SVG·내장 Pretendard를 사용합니다. 모든 본문 타이틀은 20px, 주간 날짜 범위와 로그는 14px, 시각과 날짜 구분선은 12px입니다.
- 완료 기록만 최신 시각 순서로 표시합니다. 로그 클릭 시 기존 매칭 결정을 이용한 골드·비용·귀속 비율 상세 창을 엽니다. 임의로 과거 기록을 다시 추정하지 않습니다.
- 메인/서브 사이드바와 구분선, 두 사이드바 위에 겹치는 하단 캐릭터·던전 영역을 유지합니다. 캐릭터명/상태와 던전명/난이도 사이 1px, 이미지/이름 사이 8px, 설정 버튼 36px / 아이콘 24px입니다.
- 하단 던전은 실제 패널이 30초 이상 보이지 않을 때 숨깁니다. 영상 등으로 이전 던전을 유지하는 동안에도 영역을 유지합니다. 관문 번호는 저장된 완료 배열 대신 현재 화면에서 관측한 상태 배열에서 읽습니다. 하단 던전 상태는 `진행 중`이며, OBS 진단 문구는 캐릭터 상태에 노출하지 않습니다. 던전명·난이도는 기록과 같은 공용 데이터 매칭을 사용하고, 일치하지 않으면 OCR 원문을 표시합니다.
- 메인/서브 사이드바와 설정 메뉴는 `sidebar` 색상(#22242F)을 공유하고, 본문은 `hover` 색상(#252834), 관문 로그에는 카드 배경을 두지 않고 보상표 목록은 `sidebar`, 일반 버튼은 `surface` 색상을 사용합니다. 사이드바와 설정 메뉴 구분선은 `border` 색상 45%의 1px이며, 하단 패널에는 `border` 색상 1px 외곽선을 적용합니다.
- 설정은 여백과 곡선이 있는 중앙 오버레이입니다. 배경 입력을 차단하고 Tab 포커스를 오버레이 안에 유지합니다. Esc/X로 닫고 설정 버튼으로 포커스를 돌립니다. 상세 창에서 Esc를 누르면 상세 창을 먼저 닫습니다.
- 사용자의 답변대로 클라이언트 선택·공용 데이터 보기/갱신·기록 전체 삭제를 설정 안에 배치했습니다. 기록 삭제는 취소 가능한 확인 창을 거친 다음 분석 작업자의 일시정지 확인을 기다려 수행하고 분석을 재개합니다.
- Google Drive 개인 계정 연결·업로드·다운로드는 2026-10-08 실제 엔진 서비스로 연결했습니다. 완료 기록 자동 저장도 지원합니다. [기능 이전](59-native-drive-migration.md)을 참고합니다. 공용 보상 데이터의 읽기 전용 갱신은 기존 기능을 유지합니다.
- 재실행은 기존 모델·OBS 작업자를 완전히 종료한 뒤 새 작업자를 만듭니다. 창을 닫거나 부모의 입력 파이프가 닫혀도 작업자 정리가 끝나야 종료됩니다.

## 검증

`--demo`는 샘플 JSON만 표시하며 분석 작업자를 시작하지 않습니다. `--demo --capture`는 기록·설정·빈 목록 화면을 1280/640/375px에서 캡처합니다.

```powershell
& ./ui/Beatrice.App/bin/x64/Release/net8.0-windows10.0.19041.0/win-x64/BeatricePC.exe --demo --capture
.venv-win/Scripts/python.exe -m unittest discover -s tests
```

통신 테스트는 임시 DB와 샘플 작업자만 사용합니다. UTF-8, C 라이브러리 출력 분리, 기존 작업자 종료 후 재실행, 일시정지 후 삭제, 부모 파이프 종료 시 정리를 확인합니다. 실제 게임 캡처·실제 개인 Drive 동작은 이번 UI 변경의 자동 테스트에서 실행하지 않습니다.

검증 결과: 전체 Python 테스트 317개 통과. WinUI 샘플 실행 종료 코드 0, 1280/640/375px 기록·설정 렌더링, 보상 상세 창, 빈 목록, 설정 열기 전후 창 크기 유지, 배경 입력 차단과 설정 버튼 포커스 복귀 통과. Release 빌드·publish 완료. NuGet 취약성 정보 조회는 재시도 후에도 서버 접근이 되지 않아 NU1900 경고가 남으며, 이번 빌드에서 보안 정보 조회 완료를 확인하지 못했습니다.

## 2026-10-07 제목 표시줄·초기화 후속 수정

흰색 Windows 제목 표시줄을 제거하고 앱의 44px 상단 영역에 최소화·최대화/복원·닫기 버튼을 넣었습니다. 창 이동은 상태 메시지 영역으로 가능합니다. 창 제어는 설정 오버레이 위에서도 동작하며 종료 시 기존 작업자 정리 절차를 유지합니다. 캡션 아이콘은 기존 에셋의 폰트·색상 규칙을 따릅니다.

메인 사이드바 버튼은 48px, 이미지 28px을 유지하면서 기본 Button Padding을 0으로 지정했습니다. 이전에는 기본 패딩으로 이미지에 주어지는 영역이 작아져 잘렸습니다. 네이티브 검증에서 28px 크기와 최소화·최대화·복원 동작을 확인했습니다.

초기화 진행 메시지는 분석/OCR 라이브러리, 캐릭터/던전/관문 요소 YOLO, 한국어 OCR, 완료 표시 모델을 각각 표시합니다. 단계별 시각과 메시지는 사용자 데이터 폴더의 `startup-progress.log`에 기록합니다. 20초 이상 초기화가 진행되면 `startup-stacks.log`에 스레드 위치를 남깁니다.

사용자 재보고 후 모듈을 미리 import하지 않는 실제 시작 경로에서 1/3 정지를 재현했습니다. NumPy, 이어서 OCR 의존 SciPy의 최초 네이티브 import가 작업자 스레드에서 멈췄습니다. 분석 라이브러리의 최초 import를 메인 스레드에서 완료한 뒤 Qt 분석 작업자를 시작하도록 수정했습니다. 공용 데이터 갱신도 모델 초기화 완료 후 시작합니다. 기존 테스트는 선행 모듈 import와 네트워크 차단 때문에 이 경로를 검증하지 못했습니다.

수정 후 `tools/probe_cold_start.py`에서 실제 엔진 시작 → YOLO/OCR → OBS → 게임 실행 대기가 7.42초, 실제 WinUI 시작 검증은 5.59초에 완료됐습니다. 둘 다 임시 데이터 경로를 사용하고 게임 창 연결만 차단하며, 라이브러리나 모델을 미리 불러오는 테스트 대체 작업자를 사용하지 않습니다. 회귀 테스트 318개 통과했습니다.

개발 환경에서는 `BeatricePC.exe --startup-check --app-root=<프로젝트 절대 경로>`로 같은 검증을 실행할 수 있습니다. 이 진단 모드는 실제 `app_launcher.py --engine --engine-startup-check` 경로를 사용하며 실제 사용자 기록에 접근하지 않습니다.

## 배포 명령

최종 관문/상태 표시 수정 후 Python 회귀 테스트는 321개 통과했습니다. 최종 색상 적용 후 Release publish와 1280/640/375px 네이티브 화면 검증도 통과했습니다. 디자인 자료와 로컬 스킬의 Git 포함 기준은 `design/README.md`를 따릅니다.

```powershell
./ui/Beatrice.App/build.ps1 -Publish
.venv-win/Scripts/python.exe packaging/build_single_exe.py
```

배포 스크립트는 준비된 `build/native-ui`를 포함합니다. 새 WinUI 소스·에셋도 기존 GPL 대응 소스 묶음에 포함하며 bin/obj와 화면 캡처는 제외합니다. 이번 작업에서 전체 SFX 생성과 별도 PC 설치 검증은 하지 않았습니다.
