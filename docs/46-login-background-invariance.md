# 최초 접속 UI의 배경 의존 보완

## 확인한 실패

2026-10-01 12:51~12:52(KST), 세션 `8dee6418f53f4795baeaf639545ab632`의
47프레임을 별도 보존했다. 서버 표는 감지했지만 선택 카드와 실제 로딩이 누락됐다.
대표 선택 카드 점수는 0.3421(기준 0.5), 로딩 점수는 0.25~0.35(기준 0.6)였다.
게임시작 버튼은 기준을 0.01까지 내린 진단에서도 후보가 없었다.
선택 카드와 버튼을 모두 요구했던 조건 때문에 이름 OCR 자체가 실행되지 않았다.

원래 자료의 배경 흐림/축소만으로는 새로운 배경에 충분히 대응하지 못했다.
기존 로딩 라벨에 주변 안내 UI를 포함한 것도 고정된 막대 형태만 학습하려는
요구와 맞지 않았다. 특정 배경 특징에 대한 내부 의존도는 직접 측정하지 않았다.

## 변경

- 기존 10클래스 캐릭터 모델을 재학습한다. 별도 모델/클래스는 추가하지 않는다.
- 선택 카드, 게임시작 버튼, 진행 막대 자체를 잘라 서로 다른 배경과 임의 위치에 합성한다.
- 크기와 밝기를 바꾸고 막대의 진행률을 변형한다. 로딩 그림/문구는 라벨에 포함하지 않는다.
- 다른 버튼과 선택되지 않은 카드는 음성 자료로 포함한다.
- 선택 카드와 그 안의 이름 영역이 탐지되면 버튼 없이도 OCR한다. 카드 밖 이름은 읽지 않는다.
- 이름 검증, 실제 로딩 관측, 종료 3회 확인, 기존 메뉴 OCR 및 기록 정책은 유지한다.

학습 생성기는 `tools/prepare_login_invariants.py`, 주석은
`data/annotations/login-invariants-1001.json`이다. 총 233장에 기존 자료와 새 합성
108장이 포함된다. 주석/합성 좌표는 오프라인에만 사용하며 런타임은 YOLO 박스를 사용한다.

10월 1일 실패 세션의 이미지와 잘라낸 UI는 학습 자료에 포함하지 않는다.
해당 세션은 `tools/replay_login_session.py`로 탐지→OCR→상태 전환을 재생 검증한다.
이 세션을 반복 확인해 개발하므로, 별도의 미관측 실사용 환경까지 일반화된다는
의미의 독립 최종 평가로 해석하지 않는다. 실제 DB는 재생 검사에서 변경하지 않는다.

## 검증 과정에서의 추가 보완

처음 합성 자료만 늘린 후보는 기존 메뉴 이름 인식이 저하되어 적용하지 않았다.
학습 자료 순서를 섞고 준비 학습 단계의 학습률을 낮춘 후보는 기존 화면 95장 중
89장에 성공했지만, 실제 실패 세션은 여전히 확정하지 못했다. 입력 해상도만
960→1280→1920으로 높이는 것도 해결책이 아니었다.

`tools/prepare_login_contexts.py`는 주변 비선택 카드와 다른 버튼이 있는 UI 줄을
다양한 위치/배경에 놓고, 원본 로딩 화면의 진행 막대 라벨과 막대를 지운 음성 자료를
추가한다. 최종 학습 후보의 자료는 `data/annotations/login-contexts-1001.json`
277장이다. 진행 막대 라벨은 얇은 막대의 경계 오차를 허용하는 위아래 여백을
포함하지만 그림과 팁 문구는 제외한다. 10월 1일 실패 세션은 계속 학습에서 제외한다.

## 최종 적용: 발광 표식과 로딩 종료 보조 검사

긴 막대 전체는 빈 검은 구간 때문에 위치와 점수가 불안정했다. 최종
`loading_progress` 라벨은 막대의 **이동하는 밝은 표식**이다. 그림, 팁 문구,
긴 빈 트랙은 탐지 대상이 아니다. 클래스 ID/모델 개수는 그대로 유지한다.
`tools/prepare_login_marker.py`가 표식을 다양한 진행 위치와 배경에 합성한다.
최종 학습 자료는 `data/annotations/login-marker-1001.json` 277장이다.

표식 자체가 애니메이션에서 흐려져 연속 누락되는 경우가 있어, 누락만으로
로딩 종료를 판단하지 않는다. 실제 표식을 감지한 프레임의 **전체 화면**을
64×64로 축소해 보관하고, 현재 전체 화면과 비교한다. 채널 차이가 35보다 큰
픽셀이 35% 미만이면 같은 로딩 장면으로 취급해 종료 확인을 막는다.
특정 화면 위치나 고정 OCR 영역은 사용하지 않는다. 화면 변화가 확인된 뒤에도
기존의 정상 캡처/탐지 부재/3회 연속 확인 조건이 필요하다.
이 보조 검사는 게임 HUD 탐지나 접속 API의 성공 응답을 뜻하지 않는다.
로딩 중 그림 전체가 바뀌면서 표식도 장시간 누락되는 경우는 추가 검증 대상이다.

비밀번호 창 뒤 이름은 밝기가 낮아 기존 글자 마스크에서 사라졌다. 탐지된
이름 영역에서만 원래 마스크가 실패한 경우 밝기를 보정한다. 98백분위 밝기가
24~120이면 200을 기준으로 보정하며, 빈 검은 영역은 OCR하지 않는다.
2개 전처리 결과 일치와 이름 반복 확인은 그대로 적용한다.
게임 메뉴/변경 확인창은 최초 캐릭터 선택 화면으로 취급하지 않는다.

활성 실행: `character-marker-1001` (10회 학습). 이전 후보들은 채택하지 않았다.
가중치 SHA-256: `c3595a1f0daadcd421e62c2de2a4387a44d4443c914b2972eb89e3394a2b9714`.
교체 전 모델/설정은 `outputs/retired-models-1001/character-before-marker/`에 보존했다.
선택 카드 기준은 0.25, 버튼 0.2, 현재 메뉴 이름 줄 0.6으로 검증 후 조정했다.
선택 이름 0.35, 로딩 표식 0.6은 유지한다. 낮은 점수의 카드만으로 이름을
확정하지 않고 포함 관계, OCR 및 반복 확인을 거친다.
