# 완료 표시 탐지 전환 (2026-09-29)

## 목적

일반 퀘스트와 같은 모양의 작은 퀘스트 완료 배너를 레이드 완료 근거에서 제외한다.
중앙의 `N관문 돌파` 또는 `던전 클리어` 표시를 별도 YOLO로 찾고 PaddleOCR로 의미를 검증한다.
관문 아이콘의 완료 상태는 최초 관측과 누락 복구를 위해 계속 사용한다.

## 모델 구성

| 모델 | 역할 |
| --- | --- |
| character-regions | 게임 메뉴, 현재 이름 줄, 전환 확인창, 대상 이름 줄, 로딩 표시 |
| dungeon-regions | 관문 레이드 패널, 관문 없는 레이드 패널 |
| dungeon-elements | 실제 탐지 패널 안의 제목, 난이도, 관문 배열과 아이콘 상태 |
| completion-overlay | 완료 문양 및 완료 문구 영역 |
| 한국어 PaddleOCR | 탐지된 글자 영역의 이름·난이도·완료 문구 읽기 |

카테고리별 완료 문양은 같은 완료 모델에 포함한다. 보상 알림이나 가변 도전과제 목록은
완료 영역 라벨에 포함하지 않는다. EasyOCR와 고정 화면 좌표/패널 비율 OCR은 사용하지 않는다.
학습 라벨의 좌표는 개별 원본 이미지에 대한 정답 박스이며 실행 시 탐지 위치로 사용되지 않는다.

## 판단 및 저장

1. 현재 던전·난이도와 전체 관문 배열이 확정되면 완료 판단용 문맥을 보관한다.
2. 해당 문맥이 있을 때 완료 모델을 실행한다. 메뉴/캐릭터 변경 중에는 실행하지 않는다.
3. YOLO가 완료 문양과 그 안의 글자 영역을 각각 하나씩 찾았을 때만 글자를 읽는다.
4. 신뢰도 0.8 이상의 `N관문 돌파`, `던전 클리어`만 허용한다. 공백은 무시하되 유사 문구를 추측하지 않는다.
5. 같은 대상으로 연속 두 관측이 일치해야 완료한다. 한 번의 표시를 다른 관문으로 바꾸어 저장하지 않는다.
6. 관문 돌파는 OCR 번호를 사용하며 확정된 관문 수를 벗어나면 거절한다. 관문 없는 레이드에는 관문 돌파를 적용하지 않는다.
7. 던전 클리어는 관문 레이드의 확정된 마지막 관문, 관문 없는 레이드는 레이드 전체 완료로 처리한다.
8. 기존 정책대로 앞선 관문 누락을 보완하며 완료만 DB/목록에 저장한다. 동일 캐릭터·던전·관문은 초기화 전 1회만 저장하며 완료 상태는 되돌리지 않는다.

컷신으로 패널이 사라져도 마지막 확정 문맥을 사용한다. 다른 제목/난이도의 OCR 후보,
관문 수 불일치, 확인된 캐릭터 변경이 들어오면 문맥을 해제한다.
패널 부재가 120초를 초과해도 해제한다. 새 던전 자체를 전혀 탐지하지 못한 경우를 완벽히
구분하는 것은 아니므로, 표시용으로 오래 보존한 이름만으로 무조건 완료시키지 않는다.

아이콘 직후 5초, 이전 배열 10초 등을 이용해 배너가 어느 관문인지 추측하던 규칙은 제거한다.
던전명 UI의 기존 10초 표시 유지 정책은 별개로 유지한다.

## 진단

`%LOCALAPPDATA%/BeatricePC/completion-diagnostics/<실행 세션>/`에 매 관측의 JSONL을 추가 기록한다.
현재 캐릭터, 원본 던전 관측, 관문 상태, 완료 YOLO/OCR 결과, 대상 관문, 저장/미저장 이유를 남긴다.
상태 변화와 저장 시점의 원본 프레임·상세 JSON은 별도로 남겨 기존 180슬롯 순환 진단에 덮어써지지 않는다.
이 디렉터리는 자동 순환 삭제하지 않으므로 디스크 사용량이 누적된다.
진단 저장 실패는 화면 인식과 DB 기록을 중단시키지 않으며 UI에 실패 이유를 표시한다.

## 검증 구분

- SAMPLE_001~004의 일부 완료 프레임은 학습에 사용한다. 같은 영상 재생은 기능 재현 검사이며 독립 정확도가 아니다.
- 별도 플레이에서 저장한 관문 돌파/던전 클리어 프레임은 추가 검증에 사용한다.
- 관문 없는 레이드의 단일 제공 완료 프레임은 학습에 포함하므로 독립 검증이라고 표시하지 않는다.
- 이동·축소한 프레임은 좌표 의존 회귀 검사이며 모든 해상도/모든 UI 배율에 대한 보장을 의미하지 않는다.
- 실시간 DB는 검증에 사용하지 않는다. 저장 검증은 메모리 SQLite에서 수행한다.

## 검증 결과

- 최종 자동 테스트 237개 통과. Windows DPAPI 검사는 일반 사용자 권한에서 수행했다.
- 던전 부모 모델에서 `quest_complete_banner`와 중복 `gate_panel` 클래스를 제거해 재학습했다.
  이전/신규 모델의 109장 패널 검사 모두 109/109 통과, 퇴행 0건.
- 던전 제목·난이도·관문 및 이동/축소 검사 92/93 통과. 실패한 1건은
  `Screenshot_260926_113907.jpg`의 축소 합성 화면으로 기존 모델도 동일 OCR 결과로 실패했다.
  이 작은 글자 OCR 한계는 이번 완료 탐지 변경으로 해결됐다고 주장하지 않는다.
- 완료 모델 라벨 29장: 학습 26장, 별도 검사 3장(완료 2장·음성 1장).
- 1차 640 입력 모델은 원본은 읽었지만 축소·이동 이미지에서 실패했다. 활성 모델로 사용하지 않는다.
- 크기 변화 0.5, 위치 변화 0.25의 학습 증강과 입력 크기 960으로 추가 학습했다.
- 네 영상에서 0.5초 간격으로 364프레임을 검사했다. 검증된 완료 문구는 수동 확인한 완료 구간에서만 나왔다.
- 같은 영상의 YOLO/OCR 결과를 확정 문맥이 있는 메모리 DB에 재생: 각 영상에서 완료 이벤트 1회,
  일반 퀘스트에서 잘못된 완료 0회. 마지막 관문의 경우 앞선 누락 관문 보완 포함.
- 세 원본 완료 이미지와 이동·0.7배 축소 이미지의 의미를 모두 읽었다. 영상 저장 검사와 합계 10/10 시나리오 통과.
- 실제 관문 레이드의 진단 180프레임 재생: 최초 완료 관문과 이후 완료 관문 저장,
  뒤늦은 중앙 클리어 표시는 `already_completed`로 처리되어 중복 없음.
- 관문 없는 레이드 진단 50프레임 재생: 15:35:42.866(한국 시간)에 `dungeon_clear` 완료 1회.
  해당 구간의 캐릭터가 미확정이므로 임시 완료로 보관했으며, 임의의 캐릭터를 지정하지 않았다.
- 활성 모델 전체로 원본부터 다시 실행한 230프레임(관문 180 + 관문 없음 50)에서도 동일 결과를 확인했다.
  관문 레이드는 아이콘 완료 뒤 중앙 표시가 들어와도 중복 0건, 관문 없는 레이드는 중앙 표시로 1건 저장했다.
  이 재생은 잘린 구간의 기록된 확정 캐릭터만 복원하며 캐릭터 이름 모델의 독립 정확도 검사가 아니다.
- 영상 검사에서 추가 완료 모델+OCR의 중앙 처리 시간은 110ms, 95백분위는 202ms였다.
  다른 CPU 학습이 함께 실행 중인 측정이며 앱 전체 처리 시간이나 실게임 FPS 보장은 아니다.

## 정리 내역

- 사용하지 않는 메뉴 보완 모델 분기와 그 패키징 코드를 제거했다.
- 던전 부모 모델의 옛 퀘스트 배너와 중복 관문 영역 클래스, 진행 관문을 시간으로 추측하던 완료 배정 코드를 제거했다.
- `ui-regions.pt`, `ui-menu-recovery.pt`, `gates-yolo26n-first.pt`를 활성 모델 폴더에서
  `outputs/retired-models-0929/`로 이동했다. 원래 경로와 해시는 manifest에 기록했다.
- 초기 관문 모델을 참조하는 오프라인 도구 3개는 보관 경로를 사용하도록 변경했다.
- 사용하지 않는 초기 관문 설정 2개를 `docs/legacy-model-configs/`로 이동했다.
- 역사적 학습 라벨·원본·복구용 모델은 삭제하지 않았다. 새 학습 산출물은 Git에서 제외한다.
- 기존 완료 기록의 `completion_banner` 근거 표시는 하위 호환을 위해 계속 표시한다.
  새 기록의 근거는 `gate_breakthrough` 또는 `dungeon_clear`이며 일반 퀘스트 배너 입력은 무시한다.
