# 1단계: 기록 규칙 초안

초기 질문표입니다. 현재 게임·장면·상태 세 종류·위치 의미가 확정되었으며 주기 관측과 변화 비교를 결합하기로 설계했습니다. 최신 내용은 [첫 이미지 해석](04-sample006.md)을 참조해주세요. 나머지 기록 식별·OCR·화면 설정은 미정입니다. 일반/활성화/완료 등의 예시 이름을 클래스에 넣지 않았습니다. `config/scene.json`은 실행 가능한 이벤트 판정 설정이 아니라 합의 내용을 남길 초안입니다.

| 결정 항목 | 필요한 답 | 왜 필요한가 |
| --- | --- | --- |
| game / scene | 첫 게임과 대상 장면 하나 | 데이터 수집 범위를 제한 |
| iconStates | 실제 상태 이름과 각 상태의 시각적 특징 | YOLO의 정답 클래스 정의 |
| positionMeaning | 위치/배열 의미 유무와 의미 설명 | 단순 개수 집계로 충분한지 판단 |
| requiresHistory | 이전 화면과 비교 여부, 비교 대상 | 한 프레임만으로 해석 가능한지 판단 |
| ocrFields | 필드 이름, 자료형, 단위, 허용 범위·누락 여부 | 글자 인식 필요성과 검증 규칙 결정 |
| confirmationRule | 언제 기록이 완성되는지 | 전환 도중의 관측을 기록하지 않기 위해 |
| eventIdentityRule | 서로 다른 두 건을 구분하는 근거 | 같은 화면 유지와 새 이벤트 구분 |
| reopenPolicy | 같은 장면을 닫았다 다시 열면 새 건인지 | 재진입 중복 방지 |
| uncertainPolicy | 가림·모호함·OCR 실패 시 보류/재관측/사용자 확인 등 | 추측한 값을 확정하지 않기 위해 |
| captureProfile | 해상도, 게임 UI 배율, Windows 배율, 화면 모드 | 첫 학습·검증 조건 고정 |

위치와 변화의 상세 설명, OCR 자료형 등은 이 문서에 추가하고, 첫 JSON에는 요약만 기록합니다. 설정 검사를 통과해도 비즈니스 로직 구현이나 기록 규칙 검증이 끝난 것은 아닙니다.

## 처음 보내주실 자료

1. 대상 장면이 보이는 원본 해상도 PNG 한 장. 아이콘이 여러 개 보이고 가능하면 각 상태가 함께 나타나는 이미지가 좋습니다. 이미지 크기를 줄이거나 메신저에서 압축하면 작은 형태 차이가 사라질 수 있습니다.
2. 한 장에 없는 상태를 보여주는 추가 이미지와 상태별 설명. 어떤 아이콘이 어떤 상태인지 표시한 설명 이미지가 있다면, 표시하지 않은 원본도 함께 필요합니다.
3. 대상이 아닌 화면 또는 아이콘이 없는 화면. 배경을 아이콘으로 오인하는지 나중에 검증할 수 있습니다.
4. 장면이 열리고 바뀌고 닫히는 짧은 영상은 가능할 때 추가합니다. 기록 확정·재열기·연속 이벤트의 구분에는 정지 이미지만으로 부족합니다. 현재 첫 수집 준비를 위해 영상이 반드시 필요한 것은 아닙니다.

이미지는 `data/raw/`에 넣고 경로를 알려주거나 대화에 첨부해주세요. 현재 수량은 정답 기준을 정하기 위한 시작 자료이며, 한 장으로 탐지 모델 성능을 확보할 수 있다는 의미는 아닙니다. 필요한 학습 수량은 상태 종류와 실제 검증 결과에 따라 늘립니다.

## 첫 목표의 완료 기준

사용자가 확정한 상태 목록으로 학습한 모델이 평가용 이미지 한 장에서 각 아이콘의 픽셀 좌표 `(x1, y1, x2, y2)`, 상태, 신뢰도를 내고 사각형 표시 이미지와 상태별 개수를 저장합니다. 좌표 원점은 이미지 왼쪽 위입니다. 누락, 오탐, 중복 탐지, 상태 혼동을 사람이 정답과 비교합니다. 이 결과는 프레임 관측이며 이벤트 기록은 아닙니다.

장기적으로는 정답 영상에 이벤트 구간과 필드 정답을 붙여 누락 이벤트·잘못 생성한 이벤트·중복·필드까지 정확한 기록을 별도로 집계합니다. 기록 지연과 게임 성능 영향은 실제 Windows 환경에서 측정합니다.
