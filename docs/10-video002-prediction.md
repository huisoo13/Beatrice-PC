# 새 영상 예측 확인: SAMPLE_VIDEO_002

기존 models/gates-yolo26n-first.pt를 그대로 사용했다. 학습이나 임계값 조정 없이 5Hz 목표로 관측했다. 모델 SHA256은 config/model.json의 값과 동일함을 전후 확인했다. OCR과 이벤트 상태 관리는 실행하지 않았다.

## 실행 결과

- 원본: 3440×1440, 약 59.998fps, 메타데이터 길이 약 30.651초.
- 순차 읽기로 1,833프레임을 얻었으며 메타데이터 1,839프레임보다 6개 적다. 끝까지 완전하게 디코딩했다고 주장하지 않는다. 원본 손상 또는 디코더 문제인지는 미확정이다.
- 153회 모델 관측, 마지막 표본 시각 30.416초. 모든 60fps 프레임에 추론한 것은 아니다.
- 136회는 2개 탐지, 17회는 0개 탐지. 1개 또는 3개 이상 결과는 없었다.
- ROI, imgsz=320, conf=0.25, iou=0.5는 기존 정지 이미지와 같다.

| 표본 기준 구간 | 왼쪽부터 모델 상태 |
| --- | --- |
| 시작~10.016초 | 완료 / 진행중 |
| 10.216~13.816초 부근 | 완료 / 완료 |
| 14.016~17.216초 부근 | 탐지 없음 |
| 17.416초~마지막 표본 | 완료 / 완료 |

2초 간격과 상태 목록 변화 시점의 대표 프레임을 직접 확인했다. 완료 전후는 실제 체크 표시와 일치했고, 탐지 없는 구간의 대표 이미지는 관문 UI가 보이지 않았다. 어두워진 뒤에도 완료 상태를 예측했다. 전체 표본의 정답 박스를 검수한 것은 아니므로 정량 정확도·누락률을 계산하지 않았다. 관문 번호 해석은 육안의 좌우 대응이며 자동 슬롯 추적은 아직 없다.

10.216초는 이번 관측에서 처음 완료를 예측한 시각으로 실제 게임 완료 시각이나 이벤트 확정 지연이 아니다. UI 부재 후 동일 상태를 다시 관측했으며, 중복 기록 방지까지 검증한 것은 아니다. 실제 서비스에서는 탐지 없음과 완료 0개를 구분하고 마지막 안정 상태를 관리해야 한다.

## 파일과 재실행

```bash
.venv-ml/bin/python tools/predict_video.py /Users/huisoo/Downloads/SAMPLE_VIDEO_002.mp4 --output outputs/video002
```

- outputs/video002/observations.json: 표본의 영상 타임스탬프, 박스/상태/신뢰도, 모델 해시, 영상 해시, 읽기 범위.
- outputs/video002/transition.png: 완료 전후 예측.
- outputs/video002/sheet_00.jpg~sheet_03.jpg: 대표 구간 육안 검토.
- outputs/video002/prediction-roi.mp4: 관문 영역만 확대한 5fps 예측 영상, 오디오 없음. 표본 시각을 화면에 표시하며 원본 60fps 연속 영상은 아니다. 153개 출력 프레임을 다시 읽어 확인했다.

순차 읽기·추론·ROI 저장 루프는 이번 Mac에서 약 6초였으나 모델 초기화와 결과 영상 렌더링은 제외한다. Windows 캡처나 게임 성능 영향을 측정한 결과가 아니다. 새 영상은 학습 데이터에 추가하지 않았다. 배경/UI가 기존 자료와 유사할 수 있으므로 다른 레이드·UI 배율까지 일반화하지 않는다.
