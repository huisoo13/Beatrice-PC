# 첫 이미지 해석과 관문 감지 방식

## 확정된 요구사항

- 게임: 로스트아크. 대상: 레이드 화면 왼쪽 위 관문 표시.
- 상태: `진행중 / 완료 / 진행 전`. 설정의 클래스 순서도 이 순서다.
- 왼쪽부터 1관문이며 아이콘 수는 해당 레이드 관문 수에 대응한다.
- 개수뿐 아니라 관문별 상태가 필요하다. 모든 레이드의 관문 수를 4개로 고정하지 않는다.

원본 `SAMPLE_006.jpg`는 3440×1440이며 `data/raw/`에 바이트 변경 없이 복사했다. 이 파일 크기는 최종 지원 해상도 확정과는 별개다. UI 배율, Windows 배율, 화면 모드, 촬영 시각과 녹화 출처는 미확인이다. SHA256: `ba9979bf3a5ee5b2b9d47eb6c9fae4ef5669d9bf0b5f5eabad76b0edcdad1e94`.

## 이미지 육안 해석 초안

| 관문 | 보이는 특징 | 해석 초안 |
| --- | --- | --- |
| 1 | 초록 체크 | 완료 |
| 2 | 초록 체크 | 완료 |
| 3 | 밝은 파란 문 | 진행중 |
| 4 | 상대적으로 어두운 문 | 진행 전 |

초안의 개수는 **완료 2, 진행중 1, 진행 전 1**이다. 전체 레이드 완료로 해석하지 않는다. 처음에는 육안 초안이었으며 사용자가 이후 이 표의 상태 대응이 맞다고 확인했다. 따라서 이 샘플의 상태 정답으로 사용할 수 있다. 모델 추론 결과는 아니다. 한 장만으로 완료 시각은 알 수 없다. 레이드 이름·난이도처럼 보이는 글자가 있어도 OCR 필드로 임의 확정하지 않는다.

## 설계 결정: 주기적 관측 + 안정화한 상태 변화

주기적 관측은 현재 무엇이 보이는지 얻는 방법이고, 변화 판단은 그중 새 완료를 구분하는 방법이다. 함께 사용한다.

1. 일정 주기로 왼쪽 위 ROI(관심 영역)를 분석한다. 전체 화면 픽셀 변화는 전투 이펙트 때문에 너무 빈번하므로 완료의 근거로 사용하지 않는다.
2. YOLO 모델 하나가 아이콘 위치와 상태를 탐지한다. ROI를 자르는 것은 입력을 줄이는 것이며 고정 슬롯의 색만 읽는 방식으로 대체하는 것이 아니다.
3. 장면 표시 여부, 배열의 완전성, 중복 박스와 상태 불확실성을 검증한다.
4. 여러 유효 관측으로 현재 상태를 안정화한다. UI에는 상태와 마지막 관측 시각, 유효/불확실/오래됨을 구분한다.
5. 동일한 레이드 진행 문맥에서 같은 관문이 비완료에서 완료로 안정적으로 변하면 완료 이벤트 후보를 만든다. 영속 기록은 문맥 식별·기록 규칙을 확정한 뒤 구현한다.

SwiftUI로 비유하면 매 관측은 입력 값, 안정화한 현재 상태는 ViewModel 상태다. 변화만 알리는 부분은 Combine의 `removeDuplicates()`와 비슷하지만, 가림·레이드 변경·앱 재시작도 다루므로 그것만으로 충분하지 않다. 단순 debounce는 신호가 계속 흔들릴 때 무기한 지연될 수 있어 후보 수명과 연속 유효 관측을 명시적으로 관리할 계획이다.

## 관측 주기의 실험 출발점

녹화 영상에서는 **초당 5회(200ms 간격), 동일 상태의 유효 관측 3회**부터 검토한다. 확정 운영값이 아니며 코드에 넣지 않았다. 규칙적 표본과 즉각적인 상태 표시를 가정하면 변화 후 안정화 대기는 약 0.4~0.6초이고 추론·검증·저장 시간은 추가된다. 실측값이나 지연 보장이 아니다.

영상으로 완료 표시의 최소 유지 시간을 먼저 확인한다. 짧으면 관측 주기와 안정화 기준을 함께 조정한다. 추론이 주기보다 오래 걸리면 처리량이 부족하므로 실측이 필요하다. 일반 프레임은 최신 프레임을 우선하며 발견한 후보 이미지는 따로 보존한다. PC 관측 주기와 Drive/iOS 갱신 주기는 별개다.

## 경계 상황의 처리 방향

| 상황 | 처리 방향 |
| --- | --- |
| 시작 시 이미 1·2관문 완료 | 기준 현재 상태로 반영. 방금 클리어한 이벤트나 완료 시각을 만들지 않음 |
| 진행중 → 완료 | 문맥·슬롯과 여러 유효 관측이 일치하면 새 완료 후보 |
| 진행 전 → 완료 | 중간 프레임 누락 가능. 유효한 기준 상태·문맥이 있다면 후보로 다룸. 진행중 관측을 반드시 요구하지 않음 |
| 완료 상태 유지 | 상태 유지. 매 주기마다 새 이벤트를 생성하지 않음 |
| 잠깐 가림·미탐지 | 진행 전·완료로 대체하지 않음. 마지막 상태와 관측 불확실성을 분리 |
| 4개 중 한 아이콘 누락 | 나머지를 재번호 매겨 4관문을 3관문으로 바꾸지 않음 |
| 긴 부재 후 복귀·다른 레이드·캐릭터 변경 | 같은 진행 문맥인지 확인하기 전 전환 확정 보류 |
| 앱 재시작 | 이전 문맥·상태 복구 또는 새 기준 관측. 단순 쿨다운으로 중복을 해결하지 않음 |

완전한 배열을 확인한 기준 관측에서 좌우 순서를 정하고 이후 공간적 슬롯 대응을 유지하는 방식을 검토한다. 최초 관측부터 누락됐다면 총 관문 수의 근거 또는 완전한 배열 관측이 필요하다. 아이콘 없음만으로 레이드 종료나 완료를 판단하지 않는다. 재열기와 재시작을 넘어 같은 건인지 판별하려면 레이드·캐릭터 등 진행 문맥의 정의가 추가로 필요하다.

## 다음 자료와 라벨링

- 이 이미지의 시각적 상태 대응은 사용자 확인 완료. 박스 좌표 검수는 남아 있다.
- 같은 레이드의 관문 완료 전후 영상: 표시 유지 시간, 이펙트, 화면 전환을 확인한다.
- 다른 관문 수, 전부 진행 전, 마지막 관문 완료 직후 이미지: 개수와 표현의 다양성을 확보한다.
- 최종 기록에 레이드 이름·난이도·캐릭터 중 무엇이 필요한지: 그에 따라 OCR 또는 수동 선택을 결정한다.

정답 박스와 YOLO txt는 아직 만들지 않았다. 상태 본체와 체크 등 구별 표시를 포함하고 연결선·재시작 버튼은 제외하는 기준을 실제 확대 검수에서 정할 예정이다. 상태 대응 미검수 초안을 학습 정답으로 취급하지 않는다. 수집 목록은 pending이며 데이터 분할은 비워 두었다.
