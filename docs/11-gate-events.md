# 단일 영상의 관문 상태와 완료 이벤트

beatrice/gates.py의 GateTracker는 이미지나 YOLO에 직접 의존하지 않고 시각과 박스 관측을 받는다. Swift의 상태를 보관하는 ViewModel처럼 마지막 안정 상태와 확인 중인 후보를 관리한다. tools/replay_events.py는 저장된 관측 JSON을 순서대로 전달하는 실행 도구다. 새 모델 학습이나 영상 재추론 없이 상태 로직만 검증할 수 있다.

## 실행

```bash
.venv/bin/python tools/replay_events.py outputs/video002/observations.json --expected-gates 2 --session-id video002
.venv/bin/python -m unittest discover -s tests -v
```

출력은 outputs/events-video002.json이다. events에 확정 이벤트, timeline에 관측별 waiting/candidate/stable/uncertain 상태가 저장된다. candidate는 아직 확인 중, uncertain은 배열을 신뢰할 수 없어서 마지막 안정 상태를 유지한다는 뜻이다. 상태가 안정돼도 UI가 나중에 안 보이면 uncertain으로 표시한다.

## 구현 기준

- 한 영상 전체를 같은 진행 세션으로 취급한다. 사람이 확인한 총 관문 수를 명령에 지정한다. 최초 탐지 개수만으로 전체 관문 수를 추정하지 않는다.
- 신뢰도 0.5 이상, 지정한 개수 모두 관측, 박스 겹침 없음, 기준 슬롯 중심과 거리 25픽셀 이내인 전체 배열만 유효하다.
- 온전한 초기 배열을 3회 확인하면 왼쪽부터 슬롯을 고정한다. 초기 완료는 기준 상태로만 반영한다.
- 전체 배열의 상태가 3회 연속 일치하면 안정 상태로 반영한다. 관측 간격이 0.6초보다 길면 연속 확인 횟수는 다시 시작한다. 마지막 안정 상태는 보존한다.
- 같은 세션에서 비완료→완료인 관문에 한 번 이벤트를 만든다. 진행 전→완료도 중간 프레임 누락을 고려해 허용한다.
- 미탐지·저신뢰·위치 불일치·이미 완료한 관문의 역행은 불확실 처리한다. 후보는 지우고 안정 상태는 유지한다. 관문 개수가 줄어도 뒤 번호를 당기지 않는다.
- 세션별 완료 관문 집합으로 중복을 막는다. 단순 시간 쿨다운이 아니다. eventID는 세션 ID와 관문 번호에서 재현 가능하게 만든다.

## 실제 검증

SAMPLE_VIDEO_002의 기존 예측 153개를 입력해 gate=2 완료 이벤트 1건을 얻었다. 첫 완료 관측은 10.215767초, 3회 확인 후 확정은 10.615522초다. 두 시각 차이 약 0.400초는 저장된 예측 사이 안정화 대기이며 실제 게임 완료부터의 총 지연이 아니다. 1관문 시작 완료는 새 이벤트로 생성하지 않았고 UI 소실 중 안정 상태를 유지했으며 17.416초 이후 복귀에서 중복 이벤트가 없음을 검사했다.

합성 테스트 8개도 통과했다: 완료 유지·복귀 중복, 시작 완료, 한 프레임 오인식, 관문 누락, 낮은 신뢰도, 겹친/이동한 박스, 긴 관측 간격, 진행 전→완료 및 시각 역행. 실제 인식 성능을 대신하는 테스트는 아니다.

## 현재 한계

총 관문 수와 같은 진행 세션이라는 사실을 사람이 지정했다. 이름·난이도·캐릭터 변경, 화면 모드·배율 변경, 새 진행 회차 구분은 아직 자동 처리하지 않는다. 영상 세션 가정 때문에 긴 UI 부재 후에도 같은 상태를 이어받는다. 실제 앱에 그대로 연결하려면 문맥 식별 또는 명시적 세션 시작/종료가 필요하다.

상태와 중복 방지 집합은 현재 메모리에만 있다. 프로그램 재시작 후 복구, SQLite 저장 트랜잭션, 동기화는 아직 없다. 같은 영상 전체를 같은 session-id로 재실행하면 같은 eventID를 얻지만 이것이 DB 중복 방지 구현을 의미하지 않는다. 다른 진행에는 반드시 다른 session-id가 필요하다. 동시에 여러 관문 상태가 흔들리면 전체 배열 3회 일치 조건 때문에 확정이 지연될 수 있으며 이후 자료로 조정한다.
