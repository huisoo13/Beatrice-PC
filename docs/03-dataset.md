# 3단계: 이미지 수집과 라벨링 준비

## 학습과 추론

학습은 사각형과 상태 정답을 반복해서 보여주어 모델의 숫자 파라미터(가중치)를 조정하는 과정입니다. 추론은 만들어진 가중치로 새 이미지를 분석하는 과정입니다. iOS에서 Core ML 모델을 앱에 넣어 예측하는 부분이 추론이고, 그 모델을 만드는 작업이 학습입니다. 일반 사물로 학습한 기본 YOLO 모델은 게임 고유 아이콘 상태를 자동으로 알지 못합니다.

이번 설계는 각 상태를 YOLO의 클래스로 삼아 **모델 하나가 위치와 상태를 함께 예측**합니다. 클래스는 Swift의 enum case처럼 정해진 상태 목록이며, 실제 상태 이름은 진행중, 완료, 진행 전으로 확정됐습니다. 이미지에서 각 표현과의 대응은 검수할 예정입니다. 위치별 의미와 개수로부터 게임 정보를 계산하는 작업은 모델 밖의 코드에서 합니다.

## 수집 단위

원본 PNG는 `data/raw/`에 보존합니다. 같은 영상 또는 연속 촬영 묶음에 하나의 `session_id`를 부여해 `data/manifest.csv`에 적습니다. 경로는 프로젝트 기준 상대 경로로 사용합니다.

| 열 | 내용 |
| --- | --- |
| image | 원본 이미지 경로 |
| session_id | 같은 녹화/촬영 묶음의 식별자 |
| split | 미정은 비워두고, 확정 후 train / val / test |
| scene_present | yes / no / unknown |
| label_status | pending / ambiguous / reviewed |
| notes | 화면 설정, 전환·가림·이펙트, 수작업 정답 개수 등 |

CSV에 SAMPLE_006.jpg를 pending 상태로 등록했습니다. 녹화 출처와 split은 미확정입니다. 텍스트 편집기로 관리할 수 있는 수집 목록이며 자동 데이터 분할 기능은 아직 없습니다.

다음 경우를 다양하게 모읍니다: 상태별 단독 사례, 적은/많은 아이콘, 혼합 상태, 배경 변화, 이펙트, 부분 가림, 전환, 아이콘이 없는 화면, 비슷한 다른 UI. 정답을 알 수 없는 사례는 별도 보관합니다. 일정 프레임 수만 채우는 것보다 실제 조건의 다양성이 중요합니다.

## 사각형 정답 기준 (실제 이미지 검토 후 확정할 초안)

각 아이콘 하나마다 사각형 하나와 실제 상태 이름 하나를 붙입니다. `CGRect`로 화면 요소 범위를 표현하는 것과 비슷합니다. 장면 전체에 한 사각형을 그리는 방식이 아닙니다.

- 모든 클래스에 일관된 범위를 적용합니다. 아이콘 본체만인지, 테두리나 상태 표시까지 포함하는지 실제 이미지를 보고 정합니다. 상태 차이를 보여주는 픽셀은 포함해야 합니다.
- 좌표는 원본 해상도 기준입니다. 라벨링 도구의 확대 배율을 원본 좌표와 혼동하지 않습니다.
- 가림이나 전환 때문에 상태를 결정할 수 없으면 임의 상태를 붙이지 않고 `ambiguous`로 보관합니다. 첫 학습에서는 해당 이미지 전체를 제외하는 편이 단순합니다. 아이콘이 있는데 그 박스만 빼면 모델은 그것을 배경으로 학습할 수 있습니다.
- 정말 아이콘이 없는 이미지도 사람이 검수하여 음성 사례로 포함합니다. YOLO 라벨 파일은 빈 파일로 둡니다. 미라벨링 이미지와 구분해야 합니다.
- 클래스 순서가 숫자 ID를 결정하므로 확정한 목록을 버전으로 보관하고 학습 중 임의로 바꾸지 않습니다.

[Ultralytics YOLO detection 형식](https://docs.ultralytics.com/datasets/detect/)은 아이콘마다 `class_id center_x center_y width height` 한 줄입니다. 좌표·크기는 이미지 너비/높이로 나눈 0~1 값이며 클래스 ID는 0부터 시작합니다. 라벨 파일은 이미지와 같은 파일명에 `.txt` 확장자를 씁니다. 실제 클래스 확정 후 도구에서 YOLO 형식으로 내보내도록 안내하겠습니다. 지금 임의 클래스나 빈 dataset.yaml을 학습용으로 만들지는 않습니다.

## 학습·검증·최종 평가 분리

train은 가중치 학습, val은 모델·임계값 조정, test는 마지막 평가에 사용합니다. test 결과를 보고 반복 조정하면 더 이상 독립적인 최종 평가가 아닙니다.

**이미지별 무작위 분할 전에 세션을 나눕니다.** 같은 영상의 인접 프레임과 같은 원본에서 만든 크롭·복사본은 반드시 같은 split에 둡니다. 거의 같은 이미지가 양쪽에 있으면 처음 보는 화면을 잘 인식하는 것처럼 착각할 수 있습니다. 서로 다른 세션도 동일 장면 복사본인지 확인합니다. 세션이 부족하면 추가 수집하며, 세 묶음이 없는데 억지로 나누고 독립 평가라고 부르지 않습니다. 비율은 상태별 충분한 사례를 확보한 뒤 정합니다.

## 이후 정지 이미지 평가

사람이 붙인 정답과 결과를 대조하여 누락, 없는 아이콘 탐지, 같은 아이콘 중복 탐지, 상태 혼동을 각각 셉니다. 상태별 개수만 맞아도 서로 다른 오류가 상쇄될 수 있으므로 박스와 상태도 확인합니다. 작은 상태 차이를 못 보면 ROI(관심 영역, CGRect로 잘라낸 이미지에 해당)를 크게 입력하는 방식부터 검토합니다. 필요성이 확인되기 전 탐지와 상태 분류를 별도 모델로 나누지 않습니다.
