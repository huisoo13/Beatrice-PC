# OCR 일괄 제출 검증

2026-10-06. 사용자가 요청한 순서 중 1단계인 OCR 일괄 처리만 수행했다. CPU 추론 설정과 OBS 프레임 대기 처리는 다음 단계 승인 전까지 변경하지 않는다.

## 적용

- 던전명·난이도의 회색/확대/반전 이미지 최대 6장을 한 번의 OCR 호출로 전달한다. 캐릭터명의 원본·확대 이미지 2장도 한 번에 전달한다.
- Paddle 내부 추론은 `batch_size=1`을 유지한다. 현재 CPU에서 2장 이상 동시 추론은 더 느려 적용하지 않았다. 묶음 제출로 호출 비용을 줄이되 기존 한 장 단위 전처리·추론을 유지한다.
- 입력과 결과 수가 다르면 오류로 처리한다. 필드와 전처리 순서대로 결과를 분리하며 기존 OCR 투표·신뢰도·확정 조건을 유지한다. 단일 이미지 인식기만 제공하는 기존 검증 어댑터도 지원한다.
- YOLO 모델·클래스·입력 해상도, OCR 모델, CPU 스레드·가속 설정을 변경하지 않았다. 로딩 문구의 조기 종료 인식 경로도 유지한다.

## 측정

현재 PC의 보존 게임 프레임에서 같은 crop과 모델을 사용해 비교했다. 모델 준비 시간을 제외하고 준비 실행 후 각 방식 3회 측정, 실행 순서를 번갈아 적용했다. 독립 정확도 검증이나 전체 앱 지연 측정은 아니다.

다중 샘플 동시 추론을 비교한 6장에서는 모든 방식의 판정이 같았지만, 순차 호출 중앙값 약 212ms에 비해 2/3/6장 추론은 약 244/248/252ms로 느렸다. `outputs/ocr-batch/benchmark-sizes.json`.

최종 일괄 제출·한 장 단위 추론 비교는 캐릭터 5장과 던전 10장, 총 15장이다. **전체 OCR 결과(텍스트·신뢰도·판정 포함) 15/15 동일**.

| 비교 범위 | 기존 순차 호출 | 일괄 제출 |
| --- | ---: | ---: |
| 15장 혼합 중앙값 | 545.4ms | 528.2ms |
| 던전 10장 중앙값 | 556.2ms | 552.5ms |
| 캐릭터 5장 중앙값 | 219.1ms | 219.8ms |

혼합 중앙값은 약 17ms 감소했지만 종류별 차이는 작고 캐릭터는 약 0.7ms 증가했다. 큰 속도 개선이나 모든 장면의 개선을 입증한 결과는 아니다. 프레임당 전체 1000ms 문제 해결 여부는 CPU 최적화와 앱 재실측에서 별도로 확인해야 한다.

비교 도구: `python -m tools.benchmark_ocr_batch --samples 30 --output outputs/ocr-batch/benchmark-queued.json`. 다양한 동시 추론 크기도 비교하려면 `--all-sizes`를 추가한다. JSON에는 실제 인식 결과가 포함된다.

## 검증과 다음 단계

전체 회귀 테스트 **288개 통과**, 변경분 공백 검사 통과. 새 테스트는 입력 순서·회색 이미지 변환·결과 수 불일치·빈 입력·복수/빈 인식 결과·필드 혼동 방지·불일치 거절을 확인한다.

실행 중인 앱은 재시작 후 변경이 적용된다. CPU 추론 최적화와 짧은 OBS 프레임 대기의 처리 개선은 사용자의 별도 승인을 받은 뒤 순차 진행한다.
