# 캐릭터 변경 대상 이름 연결

확인창의 대상 이름을 보관하고, 확인창 이후 실제 로딩 표시가 검증되면
화면에 `대상 이름 · 변경 중`을 표시한다. 확인창만 열거나 취소한 경우에는
기존 캐릭터를 유지한다. 같은 확인창에서 OCR 한 프레임이 실패해도 앞서
검증한 이름을 보존하지만 새 확인창에는 이전 대상을 재사용하지 않는다.

전환 중에는 이전 캐릭터의 저장 세션과 던전 완료 문맥을 해제한다.
정상 캡처에서 로딩 표시가 사라진 관측이 3회 연속 들어오면 대상 이름을
확정한다. 던전 입장이나 메뉴 재개방은 필요하지 않으며 마을에서도 동작한다.
이후 완료 기록은 새 캐릭터로 연결된다.

`CharacterVision.loadingAbsent`는 현재 프레임의 로딩 표시·확인창·메뉴가 모두
YOLO에서 missing이고, 전체 프레임에서 밝기 24 초과 픽셀이 1%보다 많을 때
제공한다. 이 밝기 검사는 검은 전환 화면 제외용이며 특정 위치를 잘라 읽지 않는다.
로딩 후보가 있지만 OCR에 실패했거나 탐지가 모호하면 종료로 처리하지 않는다.
캡처 누락, 검은 화면, 로딩 재등장, 관측 간격 초과는 연속 확인 횟수를 초기화한다.
일반 맵 이동은 앞선 캐릭터 변경 확인창→로딩 흐름이 없으므로 이름을 바꾸지 않는다.

실제 메뉴 이름을 다시 읽는 기존 경로도 유지한다. 대상 이름과 다른 실제 이름이
연속 관측되면 실제 이름으로 정정한다. 로딩 시작 후 120초 내에 접속 증거가
없으면 대상 이름 자동 확정을 포기하고 실제 이름 확인을 기다린다.
새 고정 좌표, 상대 영역 crop, 모델 변경은 없다. 기존 YOLO/OCR 관측을
상태 추적기에 연결했다. DB는 기존처럼 완료 기록만 저장한다.

검증: 전체 테스트 243개 통과. 마을에서 던전 정보 없이 자동 확정한 뒤 새
캐릭터에게 완료 기록이 저장되는 흐름, 취소, 로딩 누락 후 재등장, 캡처 실패,
검은 화면, 불확실한 탐지, 관측 간격 초과, 시간 만료를 검사했다.
라이브 DB를 수정하지 않고 메모리/임시 DB를 사용했다. Windows 암호화 검사를
포함한 전체 테스트는 일반 사용자 권한으로 실행했다.
실제 게임에서 이번 전환 흐름을 재검증해야 한다.
