# 던전 이름과 난이도 추가

사용자가 관문 표시 위의 던전 이름과 난이도를 관문 상태와 함께 최종 데이터에 포함하도록 확정했다. config/scene.json의 ocrFields는 dungeonName, difficulty다. 해당 화면에 표시되는 이름을 우선 기록하며 보스 이름이나 임의 약칭으로 바꾸지 않는다.

## 역할과 입력

같은 원본 프레임에서 이름 영역, 난이도 영역, 아이콘 영역을 각각 읽는다. YOLO26n은 기존 세 아이콘 상태를 그대로 학습한다. 텍스트를 YOLO 상태 클래스로 추가하지 않는다. OCR 엔진은 아직 선택하거나 실행하지 않았다.

상위 ROI에는 던전 이름과 난이도까지 포함해야 한다. 그 안에서 OCR용 텍스트 영역과 YOLO용 아이콘 영역을 나눌 수 있다. 기존 확대 검수 화면의 crop은 텍스트 일부를 잘라내므로 전체 분석 ROI로 재사용하면 안 된다. 원본 이미지를 보존했기 때문에 아이콘 라벨을 다시 만들 필요는 없다.

## 관측 데이터 초안

아래는 구조 설명용이며 자동 추출한 결과가 아니다. 인식 전 상태를 표현한다.

```json
{
  "schemaVersion": 1,
  "dungeonName": {"value": null, "rawText": null, "status": "unread"},
  "difficulty": {"value": null, "rawText": null, "status": "unread"},
  "gates": [],
  "gateObservationStatus": "unread",
  "recordStatus": "pending"
}
```

실제 관측에는 프레임 식별자와 관측 시각을 추가한다. gates 각 항목에는 관문 번호·상태·위치·신뢰도를 둔다. 빈 gates가 관문 0개를 의미하지 않도록 관측 상태를 따로 둔다. 문자열 필드도 null이 미판독임을 나타내며 추측한 던전 이름으로 채우지 않는다.

## 검증과 이벤트

- OCR 원문을 보존하고 공백·대괄호 등의 정규화는 별도 값에 적용한다. 실제 난이도 종류를 노말/하드 두 개로 임의 제한하지 않는다.
- 여러 프레임에서 텍스트와 아이콘을 함께 안정화한다. 제목 판독 실패 시 현재 아이콘 관측은 남길 수 있지만 필수 문맥이 검증되지 않은 새 이벤트는 확정하지 않는다.
- 이전 이름을 조용히 재사용해 새 장면의 아이콘에 붙이지 않는다. 마지막 확인 문맥 표시와 이번 프레임에서 실제 읽은 결과를 구분한다.
- 던전 이름 또는 난이도가 바뀌면 기존 관문 상태와 바로 비교하지 않고 새 문맥 후보로 다룬다. OCR 오독 한 번으로 문맥을 전환하지 않는다.
- 이름+난이도+관문 번호만으로 영구 eventID를 만들면 다른 캐릭터나 다음 회차의 클리어가 충돌할 수 있다. 캐릭터·진행 세션 등 한 건의 기준은 여전히 별도 결정이 필요하다.

## 진행 상태

신규 이미지 6장·16박스의 사용자 검수를 반영해 기존 자료와 합계 10장·26박스가 승인됐다. 이 승인은 아이콘 박스와 상태에 대한 것이며 던전 이름·난이도의 OCR 정답이나 성능이 검증됐다는 뜻은 아니다.

다음에는 텍스트까지 보이는 영역을 추출하고 이미지별 던전 이름·난이도의 정답 목록을 만들어 검수한다. 이후 YOLO26n 결과와 OCR 결과를 같은 프레임 관측으로 결합하고, 최종 이벤트 확정은 여러 프레임 검증 이후에 수행한다.
