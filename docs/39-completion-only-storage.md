# 완료 관문만 저장

2026-09-27. 사용자의 요청에 따라 DB와 리스트에 완료된 관문만 남기도록 변경했다. 이전 문서의 전체 관문 상태 저장 정책을 대체한다.

## 처리 흐름

- YOLO·OCR와 전체 관문 배열 검증은 유지한다. 진행 전·진행 중·완료 배열은 `GateTracker` 메모리에서 추적한다.
- 안정화된 배열 중 완료 관문만 SQLite `gate_states`에 저장한다. 진행 상태만 변하면 DB 쓰기와 Drive 업로드 예약은 발생하지 않는다.
- 완료 배너의 대상 관문은 DB의 진행 행 대신 메모리의 최근 확정 배열에서 찾는다. 관문 아이콘이 잠시 없어도 기존 10초 유효 범위와 배너 검증 정책을 유지한다.
- 최초 관측 완료 저장, 후속 관문 완료에 따른 앞 관문 보완, 완료 잠금, 동일 캐릭터·던전·관문 중복 방지는 유지한다.
- 캐릭터 미확정 시에도 완료만 보류 저장한다. 이름 확정 시 완료 행을 연결하며, 저장된 행 수가 아닌 실제 전체 관문 수 메타데이터를 사용한다.
- 앱 재시작 시 진행 상태는 다시 관측한다. 저장된 완료는 다시 읽어 잠금과 중복 방지에 사용한다.

## 기존 DB와 Drive

DB 버전을 3에서 4로 올린다. 다음 앱 실행에서 Store를 열 때 기존 `진행 전`·`진행중` 행을 트랜잭션으로 삭제한다. 완료 및 캐릭터 미확정 완료는 보존한다. 기존 완료 내용과 시각, ID, 업로드 대기 번호는 유지하며 이 정리만으로 새 업로드를 예약하지 않는다. INSERT/UPDATE 트리거도 미완료 행 저장을 거부한다.

Drive 내보내기는 완료만 포함한다. 과거 JSON의 진행 상태는 호환성을 위해 읽고 검증하지만 로컬 복원에서는 제외한다. 복원 확인 창에 제외 건수를 표시하며 기존 PC 기록의 백업·전체 교체 방식은 유지한다. 완료만 있는 부분 배열도 허용하고, 원격 기록의 완료 행 수를 실제 전체 관문 수로 간주하지 않는다. 관문 없는 레이드의 외부 관문 번호 0 및 recordID/updatedAt 계약은 유지한다.

옛 오프라인 이벤트 API는 별도 완료 이벤트/체크포인트 호환 경로로 남는다. 현재 실시간 실행의 진행 상태는 그 체크포인트에 저장하지 않는다. 이번 작업은 실제 사용자 DB를 도구로 직접 수정하지 않았으며 앱 재시작 시 마이그레이션이 적용된다.

## 검증

아래 122프레임은 이전에 저장한 실제 게임 화면 이미지 122장을 시간 순서대로 새 코드에 입력한 재생 검사다. 초당 처리 횟수(FPS)나 이번 변경 이후 새로 수행한 실시간 게임 테스트를 뜻하지 않는다.

- 전체 자동 테스트 205건 통과 (`outputs/completion-only-tests-final.log`). Windows DPAPI 검사는 샌드박스에서 실패해 일반 Windows 권한으로 재실행했고 전체 통과했다.
- 진행 상태 DB 쓰기 0건, N관문 완료 보완, 완료 잠금·재시작, 완료 저장 실패의 원자적 롤백 및 재시도 검사.
- 보류 완료의 캐릭터 연결과 전체 관문 수 유지, v3→v4 마이그레이션의 완료·업로드 대기 보존, 직접 SQL 미완료 삽입/갱신 거부 검사.
- 배너 대상의 메모리 추적, 중복 방지, 무관문 레이드, 일반 퀘스트 제외 및 Drive 부분 완료 복원 검사.
- 실게임 재생 122프레임 통과: 관문 레이드 46프레임에서 1관문 완료 1건만 저장하고 2관문 진행 중은 DB에 남기지 않았다. 무관문 76프레임에서 레이드 전체 완료 보류 기록 1건만 저장했다. 원본 구간의 캐릭터가 미확정이므로 보류 상태는 정상이다. 메모리 SQLite에서 수행했으며 결과는 `outputs/completion-only-gated*`, `outputs/completion-only-gateless*`에 보존했다.

모델과 탐지 영역은 변경하지 않았고 재학습하지 않았다. 실행 중인 앱을 완전히 종료하고 다시 실행해야 새 정책이 적용된다.
