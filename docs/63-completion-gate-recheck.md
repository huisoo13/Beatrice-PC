# 완료 배너를 관문 재확인 트리거로 변경

2026-10-08

## 원인과 변경

구원의 종탑 3단계에서 첫 관문 이후 표시된 `던전 클리어`는 실제로 탐지된 문구였다. 기존 LiveCoordinator는 이 문구를 마지막 관문 완료로 간주했다. 배너 때문에 아이콘을 읽지 못한 프레임에도 확인된 던전 문맥을 사용하여 2관문을 저장했다.

관문이 있는 콘텐츠의 `N관문 돌파`와 `던전 클리어`는 두 관측에서 확인되면 재확인을 요청한다. 배너가 관문 완료 상태를 만들거나 앞 관문을 일괄 완료하는 경로는 라이브 분석에서 사용하지 않는다. 일반 클리어 문구에 마지막 관문 번호도 부여하지 않는다. 실제 아이콘은 기존 StateSession/GateTracker에서 새 관측 3회를 확인하여 저장한다. 배너가 없어도 일반 관문 분석은 계속한다.

재확인 중 루프의 목표 간격은 500ms에서 100ms로 줄인다. 분석 시간이 이보다 길면 실제 간격도 길어진다. OBS의 새 프레임 공급 검증은 기존대로 적용한다. 재확인은 안정된 관문 배열 확인, 10초 만료, 다른 던전·난이도, 캐릭터 전환, 캡처 중단 시 종료한다. 완료 아이콘이 없어도 확인된 미완료 배열이면 재확인은 종료하며 일반 관측을 유지한다.

명시적으로 `gateless`로 탐지된 콘텐츠의 확정된 제목·난이도와 클리어 배너 저장은 유지한다. 아이콘이 안 보이는 것만으로 관문 없는 콘텐츠로 간주하지 않는다. 기존 다관문 배열과 불일치하는 단일 슬롯도 기존대로 차단한다. 이번 변경은 모델·클래스·탐지 좌표·신뢰도 설정을 변경하지 않는다.

## 검증

- 전체 Python 테스트 346개 통과.
- 관문 배너 단독 저장 차단, 단일 관문도 아이콘 필요, 연출 중 배너, 만료·다른 제목·캡처 중단, 아이콘 저장·중복 방지, 관문 없는 콘텐츠 저장·실패 재시도 확인.
- 보존된 세션 `20261008T120532Z-8d2bc4b7`의 8700~9540번, 841개 인식 관측을 독립 메모리 DB에서 재생했다. 새 모델 추론을 다시 수행한 검증은 아니다.
- 22:34:15.611817(KST) 1관문은 아이콘으로 저장. 22:34:24.082835의 배너에서는 재확인만 요청하여 2관문 오기록을 차단.
- 실제 두 완료 아이콘은 22:40:56.033637부터 관측되어, 세 번 확인된 22:40:57.268962에 2관문을 `direct` 근거로 저장. 이후 배너에서도 중복 저장 없음.

재생 명령:

```powershell
.venv-win/Scripts/python.exe tools/replay_gate_recheck.py <completion-diagnostics 세션 경로>
.venv-win/Scripts/python.exe -m unittest discover -s tests -q
```

앱을 완전히 종료하고 다시 실행해야 적용된다. 실제 사용자 DB·Drive의 기존 오기록은 이 작업에서 수정하지 않았다.

## 배너 화면 원시 탐지 확인 및 실게임 테스트

2026-10-09 사용자가 관문 1개 콘텐츠 클리어와 다관문 콘텐츠의 중간 배너·최종 완료를 확인하는 실게임 테스트를 완료했다고 알렸다. 이 확인은 사용자 보고이며, 새 실게임 로그를 별도로 재분석한 결과는 아니다.

앞선 진단에서 `gates=[]`는 개별 아이콘 미탐지를 뜻한다고 단정할 수 없다. DungeonObserver는 제목·난이도가 검증되지 않으면 탐지된 관문 결과도 비운다. 해당 배너 프레임의 기존 진단은 제목 영역 누락 또는 영역 밖(`text_region_missing_or_outside`)이었다.

현재 활성 모델을 배너 이미지 두 장에 직접 실행한 결과:

| 프레임(KST) | 1관문 | 2관문 |
|---|---|---|
| 22:34:24.082835 | 완료 98.04% | 진행 중 97.21% |
| 22:41:07.590166 | 완료 97.85% | 완료 98.18% |

이 값은 현재 모델로 다시 계산한 원시 탐지 점수이며, 당시 최종 관측에 저장된 점수는 아니다. 탐지 점수는 완료 판단의 정확도 확률과도 다르다.

제목 OCR 검증에 실패한 배너 화면에서도 기존 확정 문맥에 새 관문 결과를 연결하는 보완은 논의만 되었으며 이번 구현에 포함되지 않았다. 현재는 제목·난이도가 다시 검증되는 새 관측에서 아이콘 상태를 확인한다. 배너 재확인 트리거와 단일·다관문 아이콘 저장 로직은 적용되었다.
