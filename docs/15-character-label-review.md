# 캐릭터 영역 라벨 초안

기존 요청 순서의 1단계 결과다. 승인된 관문 라벨과 별도로 data/annotations/character-review-v1.json에 6장·12박스를 pending으로 기록했다. 사용자 검수 후에만 학습용 정답으로 전환한다.

클래스는 current_name(초상화 아래 현재 이름), target_name(변경 확인창 대상 이름), switch_dialog(변경 확인창 전체)다. 이름 박스에서는 Lv.70, 장비 레벨, 장식을 제외했다. 이름 문자열은 OCR 정답 필드에 별도 기록했다. YOLO에는 실제 이름을 클래스 목록으로 넣지 않는다.

| 이미지 | 장면 | 현재 이름 초안 | 대상 이름 초안 |
| --- | --- | --- | --- |
| C1 | 최초 접속 후 메뉴 | 후이수 | 없음 |
| C2 | 성공 경로의 변경 확인창 | 후이수 | 테베체 |
| C3 | 성공 후 메뉴 재확인 | 테베체 | 없음 |
| C4 | 취소할 대상 확인창 | 테베체 | 힐레우스 |
| C5 | 취소 후 선택 목록 | 테베체 | 없음 |
| C6 | 다른 대상으로 재선택 | 테베체 | 후이수 |

current_name은 그 위치에 보이는 이름 영역의 의미다. 자동 상태 확정은 별도의 시간 흐름과 접속 완료 검증을 거쳐야 한다. C5에서 확인창은 없지만 선택 목록 오른쪽 위에 힐레우스 이름이 남는다. 이 이름은 현재 캐릭터 이름으로 라벨링하지 않았다. 변경 대상 이름은 팝업 중앙 영역만 사용한다.

원본 프레임을 data/raw/character-review에 바이트 그대로 보존하고 해시, 기존 영상별 그룹, 대략적 영상 시각을 기록했다. 성공·취소 후 상태 해석은 육안 초안이며 자동 모델/OCR 결과가 아니다. 인접 프레임의 학습/평가 분할은 하지 않았다.

outputs/character-label-review/page1.png 및 page2.png에 전체 영역과 이름 확대를 함께 표시했다. 렌더링 후 직접 열어 글자가 박스에 포함되고 레벨 숫자는 제외되는지 확인했다. 사용자에게는 박스 범위와 실제 이름 철자 검수를 요청한다. 초기 선택 화면과 로딩 장면의 감지·보류 로직은 이후 추가 구현 대상이며 이 3클래스만으로 모든 전환 판단이 완성된 것은 아니다.

재생성: `.venv-ml/bin/python tools/render_character_review.py`. 현재 렌더러 글꼴은 macOS 한국어 글꼴을 사용한다. OCR 엔진 설치, YOLO 캐릭터 모델 학습, 캐릭터 흐름과 저장 모듈 연결은 다음 단계다.
