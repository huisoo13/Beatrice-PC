# 던전 제목 첫 숫자 탐지 보강

2026-10-11. `1막: 대지를 부수는 업화의 궤적 / 싱글 모드`의 제목 첫 숫자 누락을 던전 요소 YOLO 추가 학습으로 보완한다.

## 원인

14:39:36 완료 화면에 `1막`이 보였지만 실제 제목 탐지 박스는 `[53, 59, 317, 89]`였다. OCR은 첫 숫자가 없는 `막: 대지를 부수는 업화의 궤적`에 약 98% 신뢰도를 반환했고, 기록도 같은 원문으로 저장돼 공용 데이터 `field_name` 매칭이 실패했다. 같은 프레임의 왼쪽 제목 범위를 늘린 조사에서는 `1막`이 정상 인식되고 공용 데이터 v16의 싱글 모드 1관문과 매칭됐다.

첫 숫자가 없는 이름에 장 번호를 추측해 붙이지 않는다. 다른 장 번호를 잘못 연결하지 않도록 공용 데이터 매칭 규칙은 유지한다. 기존 잘못 저장된 기록은 이번 모델 교체만으로 자동 수정되지 않는다.

## 학습 자료

- 기존 89장의 요소 학습 자료를 유지한다.
- 같은 실제 플레이의 실패 원본 4장(19·63·75·113)을 추가한다. 부모 패널을 탐지한 위치에서 잘라 학습하며 제목 라벨은 첫 숫자와 마지막 글자를 모두 포함하도록 검토했다.
- 원본마다 밝기 100%·75%·50%·35%, 크기 75%·125% 및 밝기·크기 조합을 만들어 28장을 추가한다. 합계 117장이다.
- 밝기 감소는 합성 dim 자료다. 실제 모든 오버레이 효과의 독립 검증으로 해석하지 않는다.
- 학습 라벨 좌표는 오프라인 자료에만 존재한다. 런타임의 탐지·OCR 범위를 고정 좌표로 바꾸지 않는다.

학습 자료 준비와 실게임 YOLO/OCR 재생은 `tools/review_title_elements.py`가 소유한다. YOLO 학습 실행은 기존 `tools/train_dungeon_panel.py`를 재사용한다. 새 런타임 모듈이나 UI·저장 필드를 추가하지 않는다.

## 검증·적용

기존 요소 탐지 퇴행, EX 하드 단일 관문 탐지, 실제 1막 전체 화면 OCR, 기존 1·2·3막 첫 숫자 OCR, 추가 자료의 제목 양 끝 포함 여부를 검사한 뒤 모델을 적용한다. 합성 자료와 학습에 넣지 않은 같은 플레이 프레임의 재생은 독립 세션 정확도 측정이 아니다.

| 검사 | 결과 |
|---|---|
| 기존 요소 89장 | 이전·신규 모두 89/89, 퇴행 0 |
| 실제 1막 전체 화면 OCR 56장 | 이전 5/56 → 신규 56/56 |
| 위 화면 중 학습 원본이 아닌 같은 플레이 프레임 | 신규 52/52 |
| 기존 1·2·3막 첫 숫자 OCR 7장 | 신규 7/7 |
| dim·크기 변형 제목 양 끝 실제 획 포함 | 신규 28/28 |
| EX 하드 전체 화면 관문 인식 29장 | 이전·신규 모두 29/29 |
| 저장·공용 매칭 연결 | 실제 완료 프레임 OCR을 메모리 DB로 저장해 field_name 매칭 확인 |
| Python 회귀 | 477개 통과 |

첫 후보는 제목 세로 여백이 커 기존 OCR의 글자 높이 검사에서 제외되는 프레임이 있어 적용하지 않았다. 세로 라벨을 글자 높이에 맞춰 보완해 12 epoch 추가 학습했다. 빈 라벨 여백의 포함 여부와 실제 글자 획의 포함 여부를 구분하며, 양 끝 획 검사는 알려진 합성 밝기를 적용한 글자 마스크로 확인한다. 이 검사는 오프라인 평가에만 사용한다. 축소·확대 자료의 경계 사례 세 장도 실제 OCR로 첫 숫자를 확인했다.

학습 입력 512, CPU 4스레드, batch/nominal batch 2, freeze 10, AdamW, 학습률 0.0002를 사용했다. 첫 학습 18 epoch 이후 세로 라벨 보완 학습 12 epoch를 수행했다. 최종 보강의 warmup은 0이다.

검증 후 `models/dungeon-elements.pt`와 설정의 학습 이력·해시만 교체했다. 7개 클래스·탐지 기준·OCR 기준·공용 매칭·완료 저장 정책은 유지했다. 캐릭터 영역·던전 부모 영역·완료 표시 모델 해시는 변경 전후 동일하다. 활성 모델 SHA-256은 `d841231be45c5294fb607be0b1a9e1c6c808bef960079b8ba0dae92a19a77434`다.

검사·학습 로그와 이전 모델 백업은 `outputs/title-elements-review-1011/`에 보존한다. 주요 결과는 `title-comparison-final.json`, `exhard-comparison-tight.json`, `memory-record.json`, `tests.log`다. 모델·원본·데이터셋은 기존 정책대로 로컬에 보존하고 Git에는 설정·학습 라벨·도구·문서를 남긴다.

앱은 모델을 시작 시 불러오므로 적용 후 재실행해야 한다. 이후 잘못 저장된 실제 1막 기록은 Store의 정정 API로 ID·관측·생성 시각을 보존하여 수정했다. 원본 DB와 정정 전후 JSON은 `outputs/gold-reward-review/`에 남긴다. 보류했던 골드 보상표 인식은 [별도 모듈 작업](65-gold-reward-recognition.md)으로 재개했다.
