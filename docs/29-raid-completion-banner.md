# 레이드 완료 배너로 관문 누락 보완

구현·활성화: 2026-09-24. 문서 점검: 2026-09-25. 기존 관문 상태 저장에 공통 퀘스트 완료 배너 탐지를 추가하고 로컬 활성 모델을 교체했습니다. 심연의 역류와 가디언 토벌 지원은 이번 범위에서 제외했습니다. 새 빌드의 사용자 실게임 검증과 다른 해상도 검증은 후속 작업입니다.

## 구현 위치와 운영 상태

| 역할 | 파일 |
| --- | --- |
| 현재 레이드 패널·배너 탐지 연결 | `beatrice/dungeon_observer.py` |
| 무관문 제목·난이도 OCR, 패널 위치 오차 보완 | `beatrice/dungeon.py` |
| 배너 연속 확인·한 노출의 대상 고정 | `beatrice/completion_banner.py` |
| 캐릭터·던전 확인과 완료 신호 결합 | `beatrice/live.py` |
| 전체 상태 원자적 갱신·완료 고정 | `beatrice/state_session.py`, `beatrice/storage.py` |

이번 변경은 기존 저장 구조를 사용하며 사용자 DB를 재생 테스트로 수정하지 않았습니다. 인식 주기와 캐릭터 모델도 변경하지 않았습니다. 2026-09-25 점검 시 소스·문서는 아직 커밋·푸시 전 작업 트리에 있습니다. 모델은 Git 제외 대상이므로 소스 푸시만으로 다른 PC에 배포되지 않습니다.

남은 파일·모델·코드 정리 판단은 [작업 후 파일 정리 점검](30-cleanup-audit.md)에 기록했습니다.

## 확인한 실제 화면

- 관문 레이드 세르카: 관문 완료 아이콘과 함께 금색 문양의 퀘스트 완료 배너가 표시됩니다. 배너 제목은 던전명과 다릅니다.
- 관문 없는 맹렬한 업화: 같은 금색 배너와 처치 완료 표시, 이후 던전 종료 패널이 나타납니다.
- 일반 퀘스트 `스치면 인연!`: 같은 배너 모양을 사용합니다. 배너만으로 레이드 완료를 구분할 수 없습니다.
- 심연의 역류의 성공 화면과 가디언의 토벌 성공 화면은 별도 형태입니다. 이들은 레이드·배너 탐지의 음성 예제로 포함하며 완료를 저장하지 않습니다.

## 탐지와 승인 조건

던전 YOLO의 기존 `dungeon_panel`, `gate_panel`에 `quest_complete_banner`, `gateless_raid_panel`을 추가합니다. 별도의 세 번째 콘텐츠 모델은 만들지 않습니다. 배너의 문양·장식·전체 외형을 탐지하며 배너 제목 OCR이나 퀘스트명 목록을 승인 조건으로 사용하지 않습니다.

관문 없는 레이드의 라벨은 **상단 단계·난이도·이름 헤더만** 포함합니다. `도전 과제`부터 버튼 위까지의 가변 영역은 라벨과 제목 OCR에서 제외합니다. 해당 영역을 비우거나 다른 배치로 바꾼 합성 예제도 사용합니다. 아직 다른 무관문 레이드 실제 화면 전체를 검증한 것은 아닙니다.

관문 패널의 YOLO 상자가 조금 위아래로 흔들려 글자 끝이 잘리는 경우를 보완했습니다. 기본 OCR이 이름·난이도를 함께 확인하지 못한 경우에만 패널 높이의 ±6%만큼 글자 영역을 옮겨 재검사합니다. 재시도 결과가 서로 다른 이름이면 채택하지 않으며 탐지 패널 바깥이나 고정 화면 좌표로 대체하지 않습니다.

배너를 완료 기록에 사용할 때는 같은 프레임에서 새로 탐지된 레이드 패널과 현재 이름·난이도가 확인되어야 합니다. 과거 이름을 표시만 유지하는 `ocr_held`, 과거 영역만 재사용한 화면, 캐릭터 메뉴, 일반 필드의 배너는 승인하지 않습니다. 관문 아이콘이 누락되어도 새 레이드 패널의 텍스트는 읽을 수 있지만, 누락을 근거로 무관문 레이드로 분류하지 않습니다.

## 완료 처리

- 관문 있는 레이드: 기존 아이콘 판정을 유지합니다. 배너 경로는 최근 10초 이내 확인한 전체 상태에서 진행 중 관문이 정확히 하나인 경우 그 관문을 대상으로 삼습니다. 대상이 불명확하면 배너만으로 번호를 만들지 않습니다.
- 관문 없는 레이드: 전용 헤더와 제목·난이도로 유형을 확인합니다. 진행 중 상태를 저장하고 배너로 레이드 전체를 완료 처리합니다. 내부 저장소의 단일 슬롯을 사용하지만 `completionScope=raid`를 붙여 화면에는 `1관문` 대신 `레이드 전체`로 표시합니다.
- 배너는 승인 가능한 연속 두 관측으로 확정하며 관측 간격이 5초를 넘으면 후보 횟수를 다시 셉니다. 하나의 배너 노출은 한 대상에 고정합니다. 배너가 계속 떠 있는 동안 다음 관문이 진행 중으로 바뀌어도 그 관문에 재배정하지 않습니다.
- 아이콘 확정 직후 5초 이내 나타난 배너는 최근 완료 관문에 연결해 다음 관문을 잘못 완료하지 않도록 합니다.
- 배너로 대상 관문을 완료 처리해도 다른 미완료 관문의 상태를 임의로 진행 중으로 바꾸지 않습니다. 뒤 관문의 확정 완료가 앞 관문을 보완하는 기존 규칙은 유지합니다.
- 기존 캐릭터·던전·관문별 단일 행, 완료 고정, 수동 전체 삭제 정책과 원자적 저장을 유지합니다. 배너 기록에는 `evidenceType=completion_banner`를 남깁니다. 캐릭터 미확정이면 임시 저장 후 해당 구간 이름 확정 시 옮깁니다.

## 검증과 범위

새 탐지 모델은 같은 해상도의 저장된 화면과 인접 프레임으로 학습·재생 검사합니다. 독립 세션 정확도나 다른 해상도 검증을 대신하지 않습니다. 일반 퀘스트 배너, 심연의 역류와 가디언의 성공 표시, 기존 캐릭터 UI·관문 레이드, 가변 하단 내용의 영향도 함께 검사합니다.

레이드 내부의 다른 일반 퀘스트가 같은 배너를 띄우는 경우까지 구분하는 규칙은 없습니다. 이번 합의에 따라 **현재 레이드 확인 + 배너**를 완료 근거로 사용합니다. 다른 무관문 레이드에서 제목·난이도 배치까지 달라지는 경우에는 추가 화면과 학습·OCR 조정이 필요할 수 있습니다.

실행 중인 앱은 코드를 다시 불러오지 않으므로 활성화 후 완전히 종료하고 `Run-Beatrice.cmd`로 재실행해야 합니다. 기존 사용자 DB에는 진단 재생으로 기록을 추가하지 않습니다.
