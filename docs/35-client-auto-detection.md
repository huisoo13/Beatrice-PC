# 시작 화면과 LOSTARK 자동 감지

2026-09-27. 현재 방식은 일반 권한의 **1초 간격 프로세스 조회**다. WMI 이벤트는 실행 경로에서 제거했으며 [이벤트 방식 검토 기록](36-process-events-investigation.md)에 남겼다.

## 최초 실행

1. 스플래시에서 YOLO와 PaddleOCR를 초기화한다.
2. 새 감시 스레드가 Windows Toolhelp API로 프로세스 목록을 즉시 한 번 조회한다.
3. 실행 파일명이 `LOSTARK.exe`인 PID만 추리고 해당 PID의 게임 창을 찾는다. 창 제목의 환경·버전 문자열은 탐지 조건으로 사용하지 않는다.
4. 탐지 여부와 관계없이 메인 화면으로 이동한다. 이후 약 1초 간격으로 프로세스를 조회하며, 최초 결과와 변경된 상태만 UI에 전달한다.

프로세스가 없으면 빨강 `클라이언트 실행 대기`, 프로세스가 있으나 창이 없으면 노랑 `클라이언트 시작 중 · 게임 창 생성 대기`를 표시한다. 프로세스가 있는 경우에만 별도로 창 생성을 확인한다. 감지됨은 초록, 화면 활성화 대기는 노랑, 실제 분석 중은 파랑이다.

## 새로고침

스플래시를 표시하고 기존 UI 확인 타이머와 분석을 중단한다. 기존 작업자가 캡처·저장 연결을 정리하고 **이전 프로세스 감시 스레드도 종료한 것을 기다린 후** 새 작업자를 만든다. 새 작업자는 모델 초기화→새 감시 스레드 생성→즉시 최초 프로세스 조회 순서로 실행한다.

이전 확인 간격, PID 목록, 조회 오류, 창 연결 및 인식 세션은 이어받지 않는다. 감시 대기는 종료 이벤트로 즉시 깨울 수 있으며, 종료 요청 중 진행되던 조회 결과는 버린다. 중복 감시 스레드를 만들지 않는다. 저장된 기록은 유지하고 분석은 시작 버튼으로 다시 시작한다.

## 실행 중 동작

- 같은 PID/창이면 기존 분석을 유지한다. 프로세스 종료·재실행으로 대상이 바뀌면 인식 세션을 초기화한다.
- 분석 중 게임이 종료되면 실행을 기다렸다가 다시 감지된 게임에서 재개한다. 사용자가 정지를 누르면 자동 재개하지 않는다.
- 프로세스 조회 실패를 화면에 표시하고 다음 주기에 재시도한다. 성공하면 오류 표시를 해제한다.
- 모델은 분석 시작/정지나 주기적 확인으로 다시 로딩하지 않는다. 새로고침에서만 재초기화한다.
- 프로세스의 이름·PID를 읽는 용도로 `TH32CS_SNAPPROCESS`만 사용한다. 게임 메모리나 모듈 목록을 읽지 않으며, 감지 기능에 관리자 실행이나 WMI 이벤트 구독이 필요하지 않다.

## 검증

`.venv-win/Scripts/python.exe -m unittest discover -s tests -q`로 전체 147개 테스트를 실행하여 통과했다.

최초 조회, 주기적 시작·종료 확인, 조회 실패 후 복구, 중복 상태 전달 방지, 대기 중 종료, 조회 도중 종료 결과 폐기, 새 감시 생성 시 즉시 재조회, 새로고침 순서를 자동 테스트로 확인한다. 실제 실게임 전체 흐름은 별도 사용자 확인이 필요하다.

일반 권한에서 실제 모델 로딩과 메인 화면 진입을 3회 연속 검증했다. 매번 이전 감시 스레드 종료와 새 감시 생성·최초 조회를 확인했고, 모델/조회 오류 및 종료 후 감시 스레드 잔존이 없었다.

## 실행 및 적용

기존 앱을 완전히 종료하고 `Run-Beatrice.cmd`를 일반 실행한다. 메인 화면에서 시작 버튼을 눌러 분석한다. 이번 변경은 소스 실행 경로에 반영했으며 별도 배포용 EXE는 다시 빌드하지 않았다. Windows 11 실기기 검증과 실게임 종료·재실행을 포함한 전체 흐름 확인은 남아 있다.
